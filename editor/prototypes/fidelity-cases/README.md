# INK-PROT-002：M0 保真验收样稿与预期字节结果

本目录为 M0 增量保真原型（INK-PROT-001）准备**独立**的输入样稿、用户动作、预期字节与验收步骤。产品基线固定为 `57aeaac18e41c7191b1be851b284aae8c1b1bbae`；规则 ID 引用 `docs/markdown-support.md@57aeaac`（冻结 1.0）。

## 独立性声明

全部输入、动作与预期仅由冻结规范、03/04/11 号票据与 2026-11-08 验收口径**独立推导**，未读取也未迎合 INK-PROT-001 原型的任何输出。交叉核验时不得用原型实际输出反向修改本目录预期；发现不一致一律记录为「通过 / 失败 / 现状差异」，不得修改样稿迁就实现。

## 验收依据（新口径优先）

1. 高级语法（公式、Mermaid、脚注、注释、callout 等）**不得**导致自动整篇退出可视编辑。
2. 畸形 / 含混边界：保留可信视图与原文、**阻止不安全的结构化保存**、由用户**主动选择**源码修复；「有提示地自动打开整篇源码模式」记为现状差异，**不判为通过**。
3. 字节判据与模式 / 交互判据**分别记录**；不得以任一模式退路默认当作新体验已满足。
4. `docs/markdown-support.md` 中 SYN-U002、EOL-001 混合换行整篇回退等旧行为仅作现状参照。

## 目录结构

## 判定类型（manifest 中 `steps[].verdict`）

| 类型 | 含义 |
| --- | --- |
| `byte-exact` | 预期字节可独立推导：manifest 的 `ops`（`find`→`replace`，`find` 必须在前一状态恰好出现一次）从前一状态推导出预期文件；这同时**证明**除声明区域外逐字节不变。`expect.to_disk=true` 表示保存后磁盘应为该字节；`false` 表示仅缓冲区态（保存被阻止或历史态）。 |
| `state-ref` | 历史步骤（Undo/Redo）：预期字节必须等于本用例更早出现过的状态（输入或此前预期文件），不单独给推导。 |
| `operational` | 无法在不知道原型界面的情况下给出字节或坐标：只给操作步骤与**内容锚点**判据（如「🎯 之后」），不捏造精确坐标或通过结果。 |

## 校验器用法

```bash
python3 editor/prototypes/fidelity-cases/verify.py
```

校验 cases.json 可解析、引用文件存在且字节/sha256/BOM/EOL/尾部换行与 manifest 一致、`byte-exact` 步骤可由 `ops` 独立重推导、`state-ref` 指向合法早期状态、无孤立文件。退出码 0 为全部通过。

## 交叉核验流程（管理者 / 原型方）

1. 在原型中打开 `input*.md`，按 `steps[].action` 逐步操作；每步记录：**通过 / 失败 / 未执行 / 现状差异**。
2. `byte-exact` 步骤用 `sha256` 比对保存后的磁盘文件（或 `to_disk=false` 时比对缓冲区字节）。
3. `operational` / `state-ref` 步骤按 acceptance 内容锚点逐条记录实际行为；`state-ref` 仍要求字节与所引状态一致。
4. 所有未执行项保持待验证；任一步失败记录最小反例（实际字节 / 截图 / 状态面板值）。

## 每用例说明

以下「编辑范围」指用户实际改动的源范围；「定界符范围」指为保持语法有效允许变化的最小外层定界符；两者之外**逐字节不得变化**（FID-002）。

### 01 中文与 emoji 局部替换

- 输入含：标题、两段中文、ZWJ 家庭 emoji（7 标量 / 25 字节）、旗帜 emoji、预组合 `café`（`63 61 66 C3 A9`）与分解 `cafe+U+0301`（`63 61 66 65 CC 81`）各一处。
- 步骤：①「原文字节」→「原始字节」；② 👨‍👩‍👧‍👦→🧑‍🤝‍🧑（25B→18B、7→5 标量、11→8 UTF-16 单元，长度变化暴露按 UTF-16 截断/偏移错位的实现）；③ 🇨🇳→🇯🇵（同字节数不同码点）；④ 观测两种重音全程不归一化。
- 不得改动：标题、另一 emoji、末段、全部换行与两种重音的字节表示。

### 02 保护片段前后空白（含 BOM）

- 输入含 4 类 D 级保护片段（`$$` 块级数学、HTML 注释内含 `[[bad`/`$x$`、脚注引用+定义、callout），以及**两个连续空行**、行尾**双空格**（硬换行候选）、正文内**制表符**；文件带 UTF-8 BOM。
- 步骤：① 不修改直接保存（FID-001：逐字节一致，含 BOM；且含 D 级片段时默认仍为可视混排，不自动整篇源码——新口径，现状回退记差异）；② 第一段 5 字改动；③ 末段 6 字改动。
- 不得改动：BOM、两个空行、行尾双空格、制表符、四类片段的全部字节、全部换行。

### 03 引用式链接不改写

- 输入含行内链接（带 title）、引用式 `[文字][label]`、折叠式 `[label][]`、快捷式 `[label]`、裸 URL、尖括号自动链接、图片引用、`\|` 转义、两条引用定义。
- 步骤：① 引用式链接文字 4 字改动；② 图片 alt 1 字改动；③ 行内链接 destination 追加 `-v2`。
- 不得改动：标签名、两条引用定义（含 title/路径）、其他链接写法、`\|`；不得把引用式改写为行内或反向归一。

### 04 任务状态单字符切换（CRLF、无尾部换行）

- 输入全 CRLF、**无尾部换行**，三项任务 `[x]` / `[ ]` / `[X]`。
- 步骤：① 点击第二项（空格→`x`）；② 点击第三项（`X`→空格）。
- 不得改动：括号定界符、列表标记、正文里普通字符 `X`、全部 CRLF；**不得自动补尾部换行**。
- 约定依赖：本样稿预期切换写入**小写 `x`**（独立预期）；若实现写其他字符，记差异并记录实际字节。

### 05 marks / attrs 修改

- 步骤：① 去「加粗」的 `**`（仅删 4 个 `*`，其他 marks 写法不归一）；② 标题 `##`→`###`（仅加 1 个 `#`，不加尾部 `#`、不改 Setext）；③ 行内代码中插入反引号，定界符按 SYN-S004 增长为双反引号 `` ``行`内代码`` ``（不加空格填充、不用三反引号）；④ 围栏 info `python`→`swift`（围栏长度/类型不变，内容与 closing fence 不变）。

### 06 split/join（CRLF）

- 步骤（main 变体，视觉）：① 段内「拆分点」后 Enter **拆分为两个段落**——CommonMark 新段落必须空行分隔，预期插入 CRLF 空行（2 个新边界均继承 **CRLF**）；只插单个 CRLF（同段落 softbreak）记为差异；② 合并回一段（**往返后字节须与输入 sha256 相同**）；③ 列表项「衔接点」后 Enter（新列表项按第 5 节用 `- ` 标记，单 CRLF；若实现为懒延续则记差异与实际字节）；④ 合并回（往返 sha256 相同）。
- softbreak 变体（源码模式）：① 段内插入单个 CRLF 软换行（继承 CRLF）；② 删除合并回（往返 sha256 相同）。该变体仅覆盖单换行 EOL 继承，不作为段落拆分判定。

### 07 Undo/Redo 粒度与字节态

- 编辑 A（3 字替换）→ 编辑 B（任务勾选 1 字符）→ 撤销 → 撤销 → 重做 → 重做。
- 预期：每次撤销只回退**一个**用户编辑（A、B 分属两个历史单元，合并即失败）；两次撤销后缓冲区与输入逐字节一致且 clean；重做逐步恢复；各中间态字节 = 对应 `after-step-N.md`。
- 磁盘态取决于何时保存，记录实际；不捏造未定义的保存点。

### 08 源码仅改格式同语义但应 dirty

- 步骤：① 视觉⇄源码来回**不输入**：不得 dirty、保存逐字节一致（模式切换不是格式化时机）；② 源码模式把 `*星号强调*` 定界符改为 `_星号强调_`：语义相同、字节不同，返回视觉模式后**必须 dirty**，保存按缓冲区字节写盘（GATE-004，不得自动改回星号），重开语义正确；③ 跨模式撤销一次回到输入字节、clean，光标落在「星号强调」附近（内容锚点）。

### 09 源码往返选区映射与跨模式历史

- 步骤：① 视觉模式光标置于 `🎯` 与 `。` 之间→切源码：光标必须映射到同一内容锚点（`🎯` 占 2 个 UTF-16 单元，不得按 UTF-16 长度落进 emoji 内部）；记录原型给出的标量/UTF-16 偏移实际值；② 源码模式在光标处输入「锚点」（预期字节给出）；③ 切回视觉：光标回到「锚点」之后、dirty；④ 跨模式撤销回到输入字节、clean、光标回 `🎯` 后；⑤ 重做恢复插入。
- 全部选区断言用内容锚点，不预设具体坐标；偏移数值以原型状态面板实际值为准记录。

### 10 畸形边界（两个变体）

- **open-malformed**（文件含无闭合的独占 `$$` 行）：① 打开：按新口径**不得**自动整篇切源码；应保留可信视图与完整原文、明确标识问题、打开不置 dirty；现状若是 SYN-U002 式整篇源码，记「现状差异」；② 不修改保存：不写盘或逐字节一致；③ 主动源码修复补一行 `$$`：保存字节=预期；重开后可视编辑、数学片段完整保留。
- **create-ambiguity**（合法文档，编辑中制造含混）：① 正常改 4 字（保存字节=预期，片段不动）；② 尾段行首输入 `$$` 回车产生无闭合围栏：**保留可信视图与缓冲区字节（给出 buffer 文件）、阻止结构化保存（磁盘保持①的字节）、标识问题并提供主动源码修复入口**，不得静默整篇源码、不得先有损序列化再修复；③ 经源码入口删除该行：保存成功、字节=①；④ 备选修复（文末补 `$$` 闭合）：仅记录实际归类与行为，不设字节判定。

### 11 LF/CRLF 混合局部插入

- 输入换行序列（8 个边界）：LF、CRLF、LF、空行 CRLF、CRLF、CRLF、空行 LF、LF。
- main 变体（源码模式单换行继承局部 EOL）：① CRLF 行末 Enter 插入新行（新边界继承 **CRLF**，结果为同段落 softbreak）；② LF 末行 Enter 插入新行（新边界继承 **LF**，原尾部换行保持）。
- visual-split 变体（视觉 Enter 段落拆分，不得降级为源码判定）：① 「第二行使用 CRLF 结尾。」行尾 Enter 创建新段落并输入文本（新空行的 4 个边界继承 **CRLF**）；② 尾段行尾 Enter 创建新段落（2 个新边界继承 **LF**，原尾部换行保持）。若混合 EOL 文档按 EOL-001 现状整篇源码、无法执行视觉 Enter，记「现状差异、未执行」。
- **字节判据**：保存后与对应 `after-step-N.md` / `visual-after-step-N.md` 逐字节一致，除声明吸收/新增边界外全部原始边界不变。
- **模式判据**：main 变体为源码字节覆盖；混合 EOL 可视结构化编辑由 visual-split 变体判定，按 EOL-001 现状整篇源码时记现状差异，不判为已满足新体验。

## 高价值边界（交叉核验优先盯）

1. 01-②：ZWJ emoji 替换的标量/UTF-16/字节三种长度不一致（25B/7 标量/11 UTF-16 → 18B/5/8）。
2. 02-①：BOM + D 级片段混排文档的零修改保存与「不自动整篇源码」。
3. 04-①②：CRLF + 无尾部换行下的单字符切换（不得补换行）。
4. 05-③：行内代码定界符最短增长（`1 对 backtick → 1 对 double-backtick`）。
5. 06-②④：split→join 往返 sha256 与输入相同。
6. 07：撤销粒度（一次撤销回退且仅回退一个编辑）。
7. 08-②：格式变体语义相同仍 dirty 并按新字节写盘。
8. 09-①④：跨模式选区映射与跨模式撤销的内容锚点。
9. 10-create-ambiguity-②：编辑中产生含混边界时「视图可信 + 保存阻断 + 磁盘不变 + 主动修复入口」。
10. 11：混合 EOL 的逐边界继承与保持。
