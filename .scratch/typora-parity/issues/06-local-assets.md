# 确定本地图片与附件的文件生命周期

## Question

离线 Sandbox 内，本地图片采用引用原路径、复制到文档旁资源目录还是其他用户可理解的策略？未命名文档、拖放/粘贴、Save As、文件移动及缺失资源分别如何处理，如何保留 Markdown 路径？

## Resolution criteria

用户确认资源归属、路径及错误恢复规则；查明所需系统 API 事实后再决策。保留离线原则，排除云图床上传。

事实输入由[本地图片约束研究](13-local-assets-feasibility.md)提供；研究不代替用户的资源策略决定，也不越过 M0 原型门槛提前实施完整图片功能。

## Comments

### 第一轮策略问题已发出

1. 建议新增拖入/粘贴图片默认复制到文档旁的“文档名.assets”目录，写入相对路径；已有 Markdown 图片引用保持原样。
2. 建议未命名文档先在沙盒恢复草稿区保存导入图片，首次保存后落到目标资源目录；取消或失败保留草稿与图片。

上述当时为待选提案。用户随后分别接受两项推荐，并明确授权“后续按照你的建议进行选择”。直接答复和管理者按授权选择的规则分列如下，不冒称用户逐项回答了后续细节。

## Answer

### 用户直接确认

1. 新增拖入/粘贴图片默认复制到文档旁的“文档名.assets”目录并使用相对路径；已有 Markdown 图片引用保持原样。
2. 未命名文档先在沙盒恢复草稿区保存导入图片，首次保存后落到目标目录；取消或失败保留草稿和图片。

### 管理者按用户授权采用的推荐规则

| 场景 | 默认行为 |
| --- | --- |
| 新图片导入 | 拖入文件保留可用原始图片字节；剪贴板只有图片数据时用系统能力编码为 PNG。生成可读且不冲突的文件名，插入对应相对 URI；复制失败不插入虚假成功引用。 |
| 已有引用 | 原文拼写、路径和 title 保留，不因打开、预览或主题变更重写；相对路径按文档位置解析，缺权限时请求实际需要的文件/目录授权，不猜测父目录已授权。 |
| 首次保存 | 恢复草稿的待导入图片在目标目录获授权并成功落盘后再完成 Markdown 保存；保存/复制失败或取消时，文档与资源继续可恢复，不 markSaved。 |
| Save As | 默认复制关联的托管资源到新文档对应的相对位置，保留原 Markdown 引用字节和原文档/资源。已有托管目录继续沿用，不仅因文档改名重命名资源目录；未托管相对引用若将失效，明确处理所需复制/授权，不能悄悄保存成断链状态。 |
| 目标冲突 | 新导入图片可在插入引用前生成唯一名称；已有引用的目标同名同字节可复用但不据此取得清理所有权，异内容冲突不覆盖，失败并引导换位置。不得为绕过冲突悄悄改已有引用。 |
| 移动与迁移 | 整体迁移 Markdown 和资源目录应保持相对关系；仅用 Finder 移动单个 Markdown 时不猜测和搬动外部文件，出现缺图则保留引用并提供重新授权/定位入口。 |
| 缺失与无权限 | 分别显示缺失/授权问题占位，保留 Markdown 和编辑内容；用户主动重新定位时，只修改对应引用的必要源范围。禁止将任意文件路径直接暴露给 WebView。 |
| 撤销与清理 | Undo/删除引用不立即删除磁盘图片；首阶段不自动清理文档旁未引用资源。恢复临时资源只在成功移交或明确放弃关联草稿后按所有权清理，不触碰来源文件、已有外部资源或其它草稿。 |
| 失败恢复 | 资源复制与 Markdown 保存不能假装是系统跨文件原子事务。跟踪本次新建资源与提交状态，失败保留可信源/dirty 和恢复资源；回滚仅处理本次创建且可确认未被引用的文件。 |

Save panel 的文档权限不视为资源目录权限；资源 broker、书签恢复、取消与并发访问，以及多文件提交细节仍需平台原型证明。上述为产品政策，尚不代表已有实现或验收通过。

### 验收出口

既有引用打开不改写；新文档插图后取消/失败可恢复；保存重开图片正确；授权充分的 Save As/整目录迁移后引用可用；权限、缺图和异内容冲突均保留原文/原资源；撤销不误删文件。具体检查矩阵交给[本地资源平台原型](14-local-assets-platform-prototype.md)。M0 完整功能门槛继续保留，政策确定不构成提前实现图片编辑器的授权捷径。
