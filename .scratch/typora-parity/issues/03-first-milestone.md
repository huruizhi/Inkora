## Answer

首个里程碑定义为“单篇技术文档的核心写作闭环”。用户已确认以上七个范围问题，本票解决范围与验收方向；不选择实现路线，不代表功能已实现或测试通过。

### 必须交付

- 打开或新建含中文、标题、有序/无序列表、引用、代码、链接、表格、任务列表和本地图片的技术文档，连续直接编辑、撤销重做、保存并重开。
- 表格、任务列表、本地图片不再触发整篇源码回退；加入用户主动查看/编辑源码的入口。
- 高级语法按已确认边界显示为受保护原文片段，允许正文与片段混排；不以高级语法的存在为由自动退出整篇可视编辑。
- 常用代码语言高亮与语言选择；文档大纲、字数统计、当前文档查找替换。
- Markdown 与本地图片资源能够保存、重新打开和迁移。资源引用/复制、未命名文档与 Save As 行为由本地资源策略票决定。

### 验收场景

1. 用可重复的中文技术文章/项目说明样稿完成“打开或新建 → 修改正文和常用结构 → 保存 → 关闭重开”，内容、表格、任务状态、链接和本地图片保持正确。
2. 在同一篇样稿中编辑表格、勾选任务、修改图片引用及代码语言，确认不会因这些已纳入能力而整篇切成源码模式；具体支持语法和操作集合在规格阶段列明。
3. 在含稳定可识别高级语法的样稿中编辑其前后正文，原文片段完整保留；未主动修改的范围满足仓库保真契约。修改原文需由用户主动选择源码入口。
4. 使用边界含混/畸形样稿时，明确标识问题，保留当前视图和原文，阻止不安全结构化保存；主动源码修复后重新验证。问题范围提示、视图可信性和恢复时机必须经过后续原型验证。
5. 执行主动源码查看/编辑、Undo/Redo、保存与重开，验证内容、dirty、光标/选区及历史符合仓库既有原则；实际模式切换契约由保真与交互决策确定。
6. 大纲能够定位章节；字数统计随正文变化；当前文档查找、替换与历史行为可验证；代码内容和语言选择保存重开后正确，高亮不改写源码。
7. 按已决定的本地资源策略完成文档及图片迁移、另存与重开；验证相对路径、缺失资源和错误反馈，不以显示成功替代路径/授权验收。
8. 在真实 WKWebView 与系统中文输入法中检查组合输入、光标选区、撤销、保存和关闭；文件冲突/保存失败保持原有保护。自动化、真实 IME、最低系统与发布证据的最终门槛由质量票细化，未执行项不得标为通过。
