# 028 交叉复核草案（待双方确认）
Status: proposed, not consensus or adopted architecture

两份第一轮意见见同目录INK-REV-028a.md和INK-REV-028b.md。共同事实：当前候选字节已承担用户文档职责；合法空白并不等于不安全文档；PM可复用，语义AST与可编辑投影不可混为一体。真实分歧是应先隔离验证还是先完成settle，以及重开后隐藏空格是否已足够证明续写与光标正确。

请交叉审查下列候选收敛路径，允许明确反对，不为一致忽略反例：
1. 只有一套公开当前文档原文字节权威，已接受可视编辑原子更新它；旧source若仅是语义缓存须如实改名/封装，不能save/source/history分别读不同truth。投影关系与字节合法性分开验证，不把doc.eq用于全部合法编辑态的提交闸门。
2. 同一PM/parser/ledger依赖，在独立验证分支/目录做一个有界的source-backed投影原型；复用现成果。这里C指验证隔离，不等于重写内核/UI；B可作为其内部迁移/落账接口，但不能只在点击save时才承认当前用户字节，也不能给每个入口再写例外。
3. 原型先覆盖a+space后停住→save→source no-op→scratch字节重开→在同一逻辑raw边界继续b→Undo/Redo；save不改投影/caret/revision/history，dirty只相对已保存原文。覆盖尾随空格、Enter后空行、space→Enter、LF/CRLF/BOM、marks/保护片段邻接；pending/真正映射不一致仍阻断unsafe save，composition期间守卫保持。不得把重开测试“字节保留”当作“续写位置正确”的证明。
4. 不承诺source-primary会让所有不可映射PM事务自动安全；仍要provenance和明确支持边界，不靠丢输入/无条件放行。重开可否隐藏空格须说明raw affinity、可达选区和下一字符位置；声明不对称本身不构成通过。
5. 一个边界契约+同一套可证伪oracle，然后一个隔离原型；若只能新增kind/入口特例而无法共享保存/源码/历史不变量，或需规范化用户投影导致caret/字节变化，判失败并比较投影表示方式，不再无期限补特例。最终物理IME和整体用户审阅必须在固定产物上集中完成。
6. 027仅保留部分证据、不接008；11 claimed、12不锁架构。以上还不是架构采纳决定，也不是M0通过。
