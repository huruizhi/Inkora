# 按任务难度与成本调度模型

用户明确要求按任务难度选择模型，使用 GPT-6-Luna、GPT-5.1-Sol、GLM-5.3 等不同档位，避免默认用 GPT-6.1-Sol 执行所有工作。每次启动以 Paseo 当前 profile/provider/model 清单和实际可用性为准。

## 调度规则

| 工作性质 | 优先选择 | 思考与升级规则 |
| --- | --- | --- |
| 文档、事实提取、样稿整理、命令执行、限定检查 | GLM-5.3 或 GPT-6-Luna | 优先 low；需要明确推理时 medium（仅模型支持时） |
| 明确边界的功能、局部缺陷、脚本与交叉核验 | GPT-6-Luna 或 GLM-5.3 | 按难度 medium/high；先限定文件、输入与验收判据 |
| 跨层架构、复杂映射/历史、难复现根因 | 先拆成可验证任务，评估中档模型结果 | 只有具体证据说明需要更高能力时采用 GPT-6.1-Sol 等高成本模型，并记录理由；不默认 high/max 或多代理扩张 |

- GPT-5.1-Sol 是用户明确提到的型号，当前 Paseo Codex 列表没有该 ID，暂不启动或猜测别名；列表中的 GPT-5.6-Sol 不视为同一型号。后续清单变化时重新核实。
- 思考级别只使用当前模型实际返回的选项。GLM-5.3 本轮支持 auto/low/high/max，不猜测 medium。
- 已有任务执行中不为换模型而无谓重启；实际终止、失败且无产物时诊断后交接。受限一次明确指令修正仍不能推进时，保留失败证据并换合适模型，不无限重试，也不直接升级最贵档。
- 缩短任务上下文，只给必要文件与固定提交；复用验收证据。代码变化才运行受影响检查，避免重复全套测试。不同 Agent 的预期与实现保持独立。
- 产物交接核查后及时归档 Agent，工作区与证据按需保留；不留空闲会话等待可能的未来任务。
