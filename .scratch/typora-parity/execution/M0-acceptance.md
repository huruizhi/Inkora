# M0 验收证据索引

范围与门槛以[已解决的路线决策](../issues/04-fidelity-route.md)和[原型票](../issues/11-incremental-fidelity-prototype.md)为准。本文件只索引证据、差异与下一步操作；不替代范围定义，不将基线测试或代理状态作为原型通过证明。

## 判据分层

| 层次 | 必须观察的事实 | 不能作为替代证明 |
| --- | --- | --- |
| 字节 | 原始输入、独立预期、实际输出及允许变更范围逐字节对照；换行/BOM/Unicode 保留 | 渲染看起来相同、PM 文档语义相等、仅保护块 raw 相同 |
| 交互与状态 | 实际操作后的模式、可信内容、选区、dirty、保存点、Undo/Redo 与 revision | 函数存在、静态截图、通过全文重建绕开映射问题 |
| 运行环境 | 明确区分纯模型/DOM、真实 WKWebView、系统中文输入法和用户审阅 | 把 jsdom 或模拟 composition 当作真实 IME 验收 |

用户最新决定优先：稳定高级片段与正文混排；含混边界保留可信视图和原文、阻止不安全保存、由用户主动源码修复。旧产品规范的自动整篇源码回退只可记录为现状差异，不计为新模式/交互判据通过。

## 独立性与交付处理

- OMP 先固定样稿和预期提交，再取得 Codex 原型提交进行交叉验证；原型实际输出不能反向决定预期。
- 发现样稿错误可提出最小证据，由管理者确认修正依据；不为使原型通过而改验收要求。
- 原型仅支持部分操作时，如实记录已验证边界与最小反例，继续修正或按路线决策比较替代方案；不把总体门槛缩减到已通过子集。
- 已研究基线 `57aeaac` 的 111 项编辑器测试不覆盖完整新原型门槛，也不代表产品路线已完成。
- 后续完整功能必须另有规格、任务与产品集成验收；原型通过只解除架构选型的证据前置。
