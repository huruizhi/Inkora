# INK-SPEC-029 原文权威与可编辑投影原型契约

状态：FROZEN v1，仅用于有界原型验收；不是生产架构 ADR，也不宣告 M0 通过。
代码对照基线：76070797f52b0b71debbc59b30ce8d4da6cd6f38（027部分成果）；当前已接收集成仍 ea63941a6ca320c5aa888eb18263c870fb361846。
判据由管理者从028两轮共识独立冻结；委员确认了原则，未声称逐行签认本JSON。实现者不得用自身输出生成或修改预期。

## 要回答的问题与范围

在保留现有 ProseMirror、锁定 parser/schema/ledger 和受保护原文片段的前提下，能否让每个已接受编辑立即进入唯一当前原文，使合法尾随空格、编辑空行、源码往返、保存和重开共享可审计契约，且不破坏光标、撤销与 composition？

只有一个隔离原型。允许复用027代码，但不直接接入008或生产，不新增依赖，不重写UI框架。原型放在 editor/prototypes/source-authority/，现有 fidelity/ 对照和冻结文件只读。原型须提供单个离线HTML、真实EditorView自由编辑、可见状态与主链引导，不能用演示按钮直接写预期文件。构建可复用现工具链；由于用户明确要求保真/历史可复核，必须运行真正断言，不能套用通用prototype技能的“不测试”建议。

## 文档与会话边界

| 概念 | 契约 |
| --- | --- |
| 当前文档原文 | 唯一公开内容权威。每个已接受视觉/源码编辑原子更新它，含BOM、EOL、尾随空格和空行。UTF-8可无损往返是本原型范围，不承诺非法编码解码。 |
| 语义解析 | 原文的派生解释，可隐藏空白；不能反向序列化覆盖原文，也不能成为所有合法状态的普遍提交闸门。 |
| 可编辑投影 | 由原文、语法和明确位置依据形成的可操作表达。与语义AST的差异必须有原文范围/锚点证明。 |
| 位置依据 | 原文UTF-16边界、可视位置、方向、affinity及原文版本的对应；不得盲找第一个相同文本、静默nearest或重置到文档头。 |
| 会话状态 | 选区、composition、源码草稿、未解决输入意图、投影位置依据与历史。不能被Save偷偷重置。 |
| 原文保存点 | 最后成功保存的同一原文。documentDirty仅由当前原文与保存点逐字节不同决定；未提交源码草稿另有draftDirty和保存阻断，不冒充已接受内容。 |

旧source若只保留最近语义快照，应明确改名/封装；candidate可成为内部实现，但最新原文、save/source/history/dirty必须读同一语义。settle只能是编辑接受时的内部迁移，不是用户必须额外点击的操作，也不能到Save才承认字节。不得对同一合法字节因加载、视觉输入、Undo或源码入口不同而给出不同内容/保存资格。

## 不变量

1. 已接受编辑的原文补丁、投影、位置依据和历史原子更新；失败保留完整原文及可解释的用户意图，不留下半提交。合法空白不能一律作为pending或无限staged。
2. 安全谓词来自当前原文/投影关系、真实含混、未解决输入意图、源码草稿和composition。瞬时拒绝诊断与内容分离；无可旅行历史的Undo/Redo不得假造成功清错误。
3. Save不改变当前原文、投影、光标/选区、原文版本、Undo/Redo或位置依据；仅成功保存收据后更新保存点。失败不markSaved。HTML内存保存点与Node scratch文件层分别报告，均不等于NSDocument/Sandbox验收。
4. 版本在接受字节变更及真正Undo/Redo后推进；选区移动、Save、源码no-op、空历史旅行不推进版本、不制造用户编辑历史。
5. 源码入口在composition守卫外总能显示完整最新原文；有效源码no-op往返不改字节/投影/选区/版本/历史。取消明确丢弃的仅为未提交草稿。
6. 同一逻辑原文边界经source→visual→实际EditorView选区→visual→source可折返；重开后续写不能落到隐藏空格之前。非法BOM前位置、半surrogate/grapheme/CRLF内部明确拒绝。
7. 历史存完整当前原文和会话锚点，Save不是编辑。新开文档epoch不恢复旧Undo栈；重开后的Undo只撤销本epoch新输入。
8. composition期间保存/模式切换/重置/旅行等动作仍守卫；拒绝或诊断刷新不得额外updateState/setText破坏marked text。真实接受输入仍按PM正常机制同步，不假称所有updateState都非法。两个composition为两个完整历史单元，不能露拼音中间态。

## 冻结主链

详见ORACLES.json PRIMARY：a+LF → 输入Space后停住 → Save → 主动源码no-op往返 → scratch写读新epoch → 在raw offset2对应的真实可视选区输入b → Undo/Redo。
预期必须依次保持 a+Space+LF、a+Space+b+LF。不能通过删Space、再输入一个字符才允许Save、Save时规范化投影、修改预期或空函数假通过。

scratch重开需真实写/读隔离临时文件并比较UTF-8字节；不触及用户文件。原文恢复不代表会话/历史跨进程恢复，raw位置由测试显式重定位，须验证映射而非直接赋假的选区字段。保存中途不允许篡改字符；每步比较原文、原文选区、真实可视选区/映射、保存资格、dirty、历史和版本。

## 辅助域与字节策略

- PARAGRAPH_ENTER按既有视觉Enter拆段语义：在原文光标插入当前行的两个EOL，原有后缀不重写。a+LF在a后Enter为a+LF+LF+LF，caret raw3；原EOF换行留作新段行尾，继续b为a+LF+LF+b+LF。这不是“单次Enter产生三个段落”；语义parser此时仍可只有一个非空段，编辑空段由位置依据表达。
- SPACE_ENTER：a+Space+LF再拆段保存、重开、在raw4续b，得到a+Space+LF+LF+b+LF。
- 段内单尾随Space后语义仍softbreak；第二Space后应是hardbreak，不抹掉两字节或无审计忽略结构变化。已用锁定markdown-it commonmark只读解析确认这两个预期。
- marks/链接/标题/列表/引用与保护片段邻接复用同一原文契约；必要语法映射规则可以存在。边界用明确affinity，不能各入口各自放行。
- 已有隐藏尾随空格重开后，既要测试插入b，也要通过真实Backspace键路径只删除空格，避免删掉前一个可见字。这是raw affinity证明，不是新功能系统。

## 真正负例与声明边界

- 未闭合数学片段：原文全部保留，正文继续可视/局部保护，结构化保存阻断，源码修复入口可达；不能变整篇源码。
- 受保护片段内部无安全映射的编辑、过期版本事务、非法Unicode/EOL内部边界：拒绝并保留内容/会话，不偷偷推进版本、历史或保存点。
- 未提交源码草稿、composition期间的命令仍按其实际状态阻断；取消或有效修复后可恢复。
- 本原型不承诺实现完整Markdown输入规则。若“# ”尚未支持，须明示拒绝并保留意图，可Undo/source修复；不能以无条件doc.eq放行骗过正向判据。若自然实现了该规则，须追加其原文/语义/选区/历史正向证明，不能删掉上述真正安全负例。旧026用“# ”触发拒绝不是长期产品需求。

## 测试接缝与证据层级

- 视觉动作必须经真实EditorView dispatch/native key路径和公开控制器，不能直接改私有字段、手供最终patch或用期望文件反哺模型。初始化/文件重开可用文档公开构造入口。
- 控制旧027分支保留；不得改fidelity/既有测试和冻结582校验。新原型对旧样稿应复用原始字节预期，旧staged/save阻断断言若因设计改变不适用须逐项说明并提供更强同意图断言，不能宣称全矩阵已通过。
- 重解析等价检查升级为可审计投影关系不等于删除检查；差异须有原文字节归属与语义证明，其他差异拒绝。
- 先最小主链，再同一个原型覆盖辅助域/负例。自动层通过后固定单一bundle，集中做真实WK、物理搜狗的连续上屏/取消/选区替换/源码往返/保存点/UndoRedo及整体用户审阅。
- 报告分开：纯数据oracle一致性、模型/DOM重放、真实WK普通输入、物理IME、scratch文件、NSDocument/Sandbox/最低OS。未做不得写通过。

## 有界失败转向

不按kind数量机械判成败；语法映射规则允许。若同一合法字节仍按入口/标签决定Save或Source资格，Save改变用户投影/光标/字节/历史，重开续写或Backspace无法保持raw边界，或只能无审计trim/全放行，则本原型失败。停止叠加staged补丁，比较显式raw-span/锚点与规范化投影+provenance等表示，沿用同一oracle；不预先声称需换PM或能无条件接受任意事务。

先一个契约、再一个有界原型。027仍为部分成果；M0票11保持claimed，12不写采纳ADR。正文修复不扩大到完整表格、云、主题、导出或生产接入。
