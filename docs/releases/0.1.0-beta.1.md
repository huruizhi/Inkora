# Inkora 0.1.0 Beta 1：本地候选

当前阶段由用户明确选择“暂时没有，先准备 Release 候选”。因此不创建公开发布、不将 dry-run 包上传为正式 Release，不请求用户重复输入法或最低系统验收。

候选版本：0.1.0 / build 2。变化与限制见 [变更记录](../../CHANGELOG.md)。源码与包的精确 SHA、架构及机器验证在候选构建完成后记入 INK-REL-118。

## 本地准备入口

`make release-dry-run` 使用正式 App bundle identifier，构建 Release archive，显式 ad-hoc 签名，生成 `Inkora-DRY-RUN.zip`、`Inkora-DRY-RUN.dmg` 与 `SHA256SUMS`。脚本只读挂载检查 DMG、解压检查 ZIP，验证离线 bundle、签名结构、权限和元数据，不启动 App、不向 Apple 提交。

这些产物不是 Developer ID 分发包，也不能作为已通过公证的版本介绍。候选仍可供本机审阅；本轮不改变 Gatekeeper 或 quarantine 设置。

## 将来正式发布

当持证发布机备齐 Developer ID Application 身份、对应 Team 与钥匙串公证 profile 后，从同一已验证源码重新执行 `make release`。不能把 ad-hoc 包换名或直接复用为正式包。正式入口及验证顺序见 [发布说明](../release.md)。

正式签名/公证、Gatekeeper/干净用户首次启动、最终桌面视觉尚未执行；这些状态与源码/机器门禁分别记录。
