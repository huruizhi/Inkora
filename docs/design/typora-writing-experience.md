# Typora 写作体验对齐

2026-11-10：用户已确认正文优先、左侧大纲按需展开、统计移至底部、表格/代码工具随光标或选中出现；公式、Mermaid 和脚注真实渲染纳入总体目标，排版后继续实现。

## 用户问题与结果

当前界面已能编辑但缺少完整文档排版，常驻工具与右侧统计挤占阅读空间。目标是在同一生产内核上建立可连续写作的安静界面，随后补齐技术内容真实呈现。原文卡片不是公式/图表的最终体验。

## 用户故事

1. 作者打开文档即阅读正文，标题、列表、引用、代码有连贯层次。
2. 作者按需打开左侧大纲，收起后释放全部侧栏宽度，统计一直在底部可读。
3. 作者在正文中移动光标时，仅相关表格/代码工具出现；工具持焦时继续可操作。
4. 作者可用键盘发现和使用大纲、查找、源码、插入及上下文工具，不依赖 hover。
5. 作者调整窗口或侧栏后，正文按实际可用空间保持合理行宽，不重复扣减留白。
6. 作者的原文、选区、历史、dirty、保存点不因排版和显隐而改变，输入法不会被重挂载打断。
7. 作者随后能直接阅读公式、Mermaid 和脚注，并始终保留完整源码、诊断和主动修复入口。

## 实施决定

- 当前原文、可编辑投影与位置依据继续遵守 ADR-0004，不改存储/保存/资源策略。
- 第一批交付排版和低干扰界面：默认收起左侧大纲、底部统计、单行主要入口、上下文工具，以及深浅色与窄窗布局。
- 排版只作用于文档可视区域，源码保留等宽字体。正文最大阅读宽度约 760px，以容器宽度而非整个 viewport 计算。
- 工具显隐由 PM 选区派生装饰和 DOM 焦点共同决定；显示工具不提交编辑事务，持焦期间不隐藏，也不因显隐推动正文布局。
- 第二批公式、第三批 Mermaid、第四批脚注各自完成离线渲染、源码操作、失败状态和真实 App 对照；在依赖与边界核对前不宣称实现。
- 不新增重复物理 IME 或 macOS 14 实机验收前置；保持现有部署目标与诚实证据层级。

## 验证接缝

优先复用现有生产 main/面板 DOM 和 runtime/EditorView 公共接缝：验证大纲/统计与工具行为、真实命令、原文/历史/保存点不变。布局与排版在真实 WK App 用自有文档查看宽/窄窗与深浅色；jsdom 不作视觉证据。纯 CSS 不增加镜像实现测试。
