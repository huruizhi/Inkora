# V3：可直接编辑的表格与任务列表

状态：功能与验收规格已冻结，实施依赖V1生产原文权威接缝；尚未实现。上游：首阶段写作闭环、ADR-0004、V1规格；规范规则仍引用docs/markdown-support.md的SYN-S009/SYN-S014及FID/EOL/ENC/WSP规则，本文件不另建语法支持级别。它们已经是S级目标，生产实现欠缺不能被改写为D级或源码回退交付。

## 目标与语法边界

在真实产品中直接编辑GFM管道表格、点击或键盘切换任务状态，能保存、关闭重开、跨模式Undo/Redo；与中文、代码、链接、本地图片和保护片段共存，不因这些常用结构导致整篇自动源码。GFM语法依据[表格](https://github.github.com/gfm/#tables-extension-)和[任务项](https://github.github.com/gfm/#task-list-items-extension-)；交互、历史与保真策略是Inkora的产品决定。

表格覆盖可选首尾管道、表头/分隔行、列对齐、零行/多行、空格宽度不齐、转义管道、行内格式/代码/链接、中文与Unicode；不把块级多行结构塞入单元格。任务覆盖普通/有序/嵌套列表中的合法标记、大小写X和其后行内内容。代码、普通段落和保护片段内的同形字符不能生成假控件。表头与分隔行列数不一致的普通Markdown不渲染假表格，不以此强制整篇源码。

## 必需交互

- 表格单元格为真实可编辑内容，支持选区替换、中文composition、原有行内格式和链接。局部文字修改只改对应源范围；必要的转义或代码定界符变化按最小外层范围处理。
- 工具栏/上下文操作必须能新建表格、在当前位置前后增删数据行和列、调整列对齐、删除表格。新建默认两列、表头+一数据行；新增列默认未指定对齐，不改变旧列标记。最后一列不提供“删除列”制造零列表格，改用明确的“删除表格”；删除全部数据行后保留合法表头与分隔行。
- Tab/Shift-Tab在格间移动，不制造dirty/history；最后数据格Tab可显式创建下一空行，创建是一个可撤销结构命令。空格/空行停住仍可保存，不依赖继续输入使临时状态收敛。正常上下/左右不越过非法Unicode边界。
- 勾选只改括号内状态字符：新勾选写小写x，取消写ASCII空格；未编辑的大写X保持。任务正文始终可直接编辑，勾选不重建整项/整表/整篇。
- 任务末尾Enter创建同列表样式的未完成任务；空任务再次Enter沿现有列表退出行为，不残留假checkbox。嵌套/缩进/序号继承原列表行为，不能改写其他项标记。
- checkbox可键盘聚焦并以Space切换，正文中的Space仍是普通输入；语义角色、checked状态和可读名称正确。表格控件能通过键盘使用，节点不是只有截图可见的不可编辑HTML。
- composition期间结构操作/勾选/导航拒绝或延后到安全边界，但不得吞掉输入法确认Enter、丢候选或偷移焦点；采用已有统一守卫，不建立另一套组合状态。

## 原文与位置契约

复用V1唯一当前原文、会话与保存点。新节点/attrs只是派生投影，不成为第二内容权威。每个编辑/结构命令带当前版本、逻辑表格/任务所有权、精确源范围和选区；过期命令在写入前整体拒绝，保留意图，不部分应用。

| 操作 | 允许改变的最小范围 |
| --- | --- |
| 单元格文字/格式/链接 | 该格文字范围及必要转义/定界符，旧列宽空格/相邻格不重排 |
| 增删行 | 对应行及其必要行尾，未修改行逐字节保留 |
| 增删列 | 各行该列与必要分隔符/新增空格；其他格已有内容/格式不变 |
| 列对齐 | 分隔行该格必要冒号，连字符长度/周围空格不格式化 |
| 任务勾选 | 单个括号内字符，其他字节不变 |
| 新任务/空行 | 当前列表标记及最小新增内容/继承EOL，不整段归一化 |

少于表头列数的数据行，缺失格可视为空；首次编辑缺失格才补其必要管道/空格。超过列数的原始单元格不得丢弃：保留精确原文归属并可提示额外内容，编辑可见格不重写尾部隐藏格。不能靠无审计trim、忽略parser/PM语义差异或给staged加保存特例通过。

表格/列表内外的BOM、CRLF/LF/mixed EOL、无尾换行、空白、引用定义、保护公式等保持原规则。新行继承当前行EOL。保存、导航、源码no-op不规范化表格或推进用户编辑历史。一般结构命令一次Undo整体恢复；同一composition一个历史单元；Redo恢复原文、真实节点/checked/对齐、方向与caret。新load/保存新epoch不伪造跨进程Undo。

## 与现有功能的集成

- 通过真实生产runtime/main/Bridge会话接线，仍由正式snapshot→NSDocument成功写入→markSaved更新保存点；不直接调用原型或测试patch按钮。
- 源码编辑同一表格/任务后返回，节点结构与原文语义一致，异常保留可信视图和完整意图，允许主动修复；不能全篇自动源码或直接重建整篇Markdown。
- 大纲与内容统计不把checkbox语法计成正文；勾选可能改变raw统计，但内容字符/写作单元不因此增加。标题/查找定位和源码替换继续按版本/epoch重验。
- 预留V6的可见文本/原文范围映射：cell文字/任务label有位置依据，checkbox和分隔符不冒充文本。V6批量替换不能跨结构分隔符制造部分应用。
- 与V4图片互通时格内/任务内图片引用仍由同一资产授权和相对路径策略加载，不由表格DOM任意读取文件；本任务不新增网络/entitlement。
- 不预设新依赖。若实施确需表格扩展库，任务须说明锁定版本、必要性、离线体积和接口，才能引入；不能因选库代替原文保真边界。

## 冻结样稿与产品验收

[12份冻结样稿](../acceptance/tables-tasks/cases.json)由管理者在实现前独立制定。标准库verify.py仅证明预期文件哈希/字节/操作推导一致，verify-tables.cjs仅用锁定markdown-it对照8份表格预期语义；两者都不是产品测试通过。

实施者须用真实EditorView/cell commands/checkbox DOM/键盘动作驱动生产，再逐步与expected.md对比。不得手供manifest.operations的补丁冒充UI实现，不能改冻结预期反哺实现。每份至少记录打开、动作、raw diff、节点语义、选区、dirty、Save/源码往返、Undo/Redo及新会话重开；保留独立正反例。

额外必测：引用/列表容器中的表格、无首尾管道、代码中的转义管道、连续反斜杠/实体、空表/最后行列删除、少格首次编辑、额外格保留、跨cell反向选区、emoji/组合字符与CRLF内部非法边界、保护片段邻接、过期命令、composition中勾选/增行/Tab/Enter不吞候选。剪贴板基本文字路径不能丢数据；矩形多格选择、合并单元格/复杂电子表格粘贴不伪称本阶段已经支持。

最终先非UI完整生产回归/lint/build，再管理者真实WK/物理中文、键盘可达和正式文件保存重开点验。未跑的层保持未验；只有整条写作闭环通过才交付V3，不因冻结样稿检查100项绿宣称功能已完成。
