# Typora 第二轮体验优化计划（待确认）

日期：2026-11-10。基线 `3e26211713ff0f78f0e90286a6125ce613b3e442`；本文件是 INK-UX-122 的对照规划，不是已批准实施规格或产品完成声明。

目标是接近 Typora 的连续阅读、低干扰操作和就地编辑体验。首轮正文排版、左侧按需大纲、底部统计、上下文工具、离线技术渲染已经交付；本轮不重复建设。真实同尺寸对照仍显示明显观感差距，详见[证据与截图](../../.scratch/typora-ui-round2/COMPARISON.md)及[官方参考研究](../../.scratch/typora-ui-round2/TYPORA-REFERENCE.md)。

## 已确定的边界

- 延续[首轮方向](typora-writing-experience.md)：正文优先、左大纲按需展开、底部统计、表格/代码工具按上下文出现。
- 当前原文、可编辑投影和位置依据仍按 ADR-0004 分工；不以 DOM 或渲染后的内容反写整篇 Markdown。
- `.assets`、未命名图片恢复、授权与保存屏障保持已定政策。图片未授权态不伪装成成功图片，也不为截图扩大用户目录授权。
- 视觉目标不是复制商业主题或所有菜单。Typora 主题/缩放尚未确认，不承诺像素一致。
- 用户不再重复物理输入法测试，不做本轮 macOS 14 专门验收；保持14+部署目标，自动接缝与当前系统证据按实际运行层级报告。

### 1. 先补入口，再收起顶栏（P1，待用户选择）

**问题：** 文档标题前仍有整行常驻模式和插入按钮。当前原生菜单没有这些命令，直接隐藏将损失可发现操作。

**范围：** 建立当前文档的原生命令路由，复用现有插图、插表、模式动作；菜单及快捷键资格与 Web 同源校验。通过后收起对应常驻按钮，保留轻量大纲/查找入口、当前模式和真正需要处理的草稿状态。源码 dirty 时提交/取消必须持续可达。原生插图按钮移走时同时解除 Web 的116px专用预留。

**可观察验收：** 普通阅读态不再出现横贯文档的完整操作条；菜单和键盘都能发现既有动作；无文档、只读、composition、dirty source draft 的资格明确；双文档只作用当前窗口；打开/取消菜单或文件面板不改原文/选区/历史。实际内容命令仍走既有局部补丁与保存屏障，不能使用无状态 DOM click 代替命令契约。

**不含：** 完整 Typora 菜单克隆、偏好系统重写、重新设计图片落盘。

### 2. 收敛阅读节奏，独立决定列宽（P1）

**问题：** h1底线到首段、连续h2/h3的间距较松；当前760px列在同尺寸宽窗比参考窄，造成更多折行。两者须分开验证。

**范围：** 先调整已证实的局部标题间距和首屏占位，再查看段落、嵌套列表、引用、表格与代码的连续层次。默认17px/1.8及760px不凭截图直接整体推翻；建议用约760/900px两档做可撤销阅读对照，再确定默认。900px是候选值，不是从Typora截图量出的精确宽度；暂不顺带搭建主题/字体设置系统。

**可观察验收：** 同窗口、同侧栏状态、同正文列宽分别比较局部间距；宽度对照另外记录折行。窄窗无横向页面滚动，长代码/表格自行滚动，标题层级不混淆；深浅色下引用和链接可辨。CSS变化不重挂载EditorView，不写原文、revision、dirty或历史。纯排版不添加镜像实现测试，以实际渲染前后证据验证。

### 3. 减少节点工具密度（P1表格；其余先核对）

**问题：** 表格已按上下文显隐，但激活后一次显示11个文字按钮。代码许可入口和图片描述入口的层级也有优化候选，实机激活/成功图片态尚待补证。

**范围：** 表格保留少量常用入口，其余行列/对齐/删除进入“更多”；不删命令。沿用Option+F10/Esc与工具持焦策略。代码优先语言操作，低频许可移到可达次级入口。图片成功态再决定描述控件显隐；失败态授权/定位必须明显可达。

**可观察验收：** 阅读时工具隐藏，进入节点后易发现，键盘能遍历全部动作；更多菜单持焦不消失，Esc回到原编辑位置；显隐不推移正文，不遮前一段，不靠hover成为唯一入口；窄窗工具不与表格横向滚动混淆。执行命令仍单次合理Undo，取消/no-op不占历史；表单和正文composition均受守卫。

### 4. 补技术内容的修改发现与导航（P2）

**问题：** “能看到”已经大部分实现，“知道如何改、读完如何返回”仍与目标有差距。块公式/脚注保持只读保护，Mermaid已经有点击进入代码。

**范围：** 先验证并清楚暴露现有安全源码路径；脚注考虑键盘可达的就近只读预览与准确返回来处。块内TeX编辑若要做，先写精确raw范围绑定、草稿apply/cancel、stale拒绝的设计，不直接使保护节点可编辑。Mermaid沿用真实代码块路径，仅处理已复现的切换/布局问题。

**可观察验收：** 成功/非法公式均能找到修改入口；取消可回到可信位置；同脚注多引用返回真实来处；预览和导航不成为内容owner、不写历史；源码提交不改范围外字节，过期意图原子拒绝；异步图表不向旧文档发布。行内数学语法扩展与图表导出不顺带纳入。

### 5. 行内 Markdown 标记显隐原型（P2，独立决策）

**问题：** Typora官方描述caret进入格式时展开源；当前普通marks是稳定结构化编辑。本轮没有完成可靠双侧实机焦点配对，不能直接选定实现。

**范围：** 先补粗体/斜体/行内代码/链接进入退出的只读实机对照；随后若用户仍要求该体验，做隔离原型，对比“保留结构化mark并补轻量操作入口”与“随选区展示原始分隔符”。限制代表子集，不直接扩展canonical语法或重写内核。

**退出条件：** 展示不变成编辑事务；保留`*`/`_`、反引号长度、转义及原始格式；正反向/跨mark选区、边缘caret、BOM/CRLF、Undo/Redo与composition安全可证。若需要把装饰文字当原文、按文本首次匹配重定位，或为了视觉效果放宽投影验证，停止并保留现有结构化路径。原型通过且用户选择后，才编生产规格。

## 当前决策前沿

1. 是否采用“先建立原生菜单与快捷键，再收起常驻顶栏”？建议采用；纯样式压缩不足以解决操作占位。
2. 是否先做760/约900px两档对照再定默认？建议采用；现有截图只能证明两者列宽不同，不能证明更宽一定更好。

以上两项本轮已向用户提出，未回复前保持待定。后续依赖它们的实施规格不当作已批准。行内标记原型、局部公式编辑和新增写作模式留在后续决策前沿，不因用户说“像Typora”自动扩大范围。
