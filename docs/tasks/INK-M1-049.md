## 红反馈与根因

- 冻结 `root-v1-final-value-review.test.ts`（SHA-256 `732e3f07b192ed8f4deb8db14eee3232c21640704a8f343a43af8270a258bc7b`）原样重放：5 例中 4 绿 1 红。DOM `compositionend` 后 10ms 先发布 `azh\n`，同 meta 迟到 final 把 runtime 改为 `a中文\n`，但只产生被 main 丢弃的 status 回调。
- 根因是 runtime 的 0ms timer 先结束 composition 并发布 logical revision，而 SourceAuthoritySession 仍允许同 composition group 聚合迟到 final；history 与 raw 正确，发布与 save barrier 却已越过稳定值。
- 锁定的 `prosemirror-view@1.42.9` 公开接口只暴露 `EditorView.composing`；pending DOM observer 与 force flush 是私有实现。本任务不调用私有 API，也不增加 composition 期间的 `updateState`。

## 本任务补正

- runtime 显式区分 `active` / `settling` / `idle`。DOM end 后，同 meta 的已接受 final 会重置 24ms quiet window；公开 `view.composing` 为 false 且 quiet window 到达后，raw、PM、selection、history、logical revision 和唯一 document 发布一起封口。
- final-before-end、final-after-end、无 post-end transaction、取消/no-op、连续两会话和下一普通事务共享同一封口规则。no-op 不制造 revision/history，也不清空 future。
- `snapshotText` 在 active/settling 均拒绝中间值；main 的 save barrier 最多等待 120ms，稳定后在同一 runtime 捕获最终 snapshot，超时或跨 load/destroy 明确返回可重试 `editor_not_ready`。
- 迟到旧 `markSaved` 只更新其精确 snapshot 保存点；当前 raw 更高时保持 dirty，不覆盖 raw、投影、selection 或 history。
- 统计与查找仍只由真实 `stateChanged` 驱动；唯一最终发布使两者与 Bridge snapshot 同时更新到最终中文，不新增协议字段。

## 任务边界

- 自动化证据是 jsdom + 真实生产 runtime/main/Bridge 接缝的 synthetic composition，不冒充真实 WKWebView 或物理搜狗验收。
- 不修改 Swift、Bridge 序列化字段、依赖或 lockfile；不包含 046 代码高亮、047 textarea reveal/搜索遮挡修复。
- 24ms quiet window 对应当前锁定 PM 的 post-end microtask/20ms cleanup 契约；升级 `prosemirror-view` 时必须重验该边界，不能把该常量当作跨版本浏览器保证。
