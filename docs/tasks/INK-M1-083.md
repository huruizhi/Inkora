# INK-M1-083：canonical 图片所有权证明

状态：非 UI 候选已实现；真实 Sandbox、系统面板、WK 显示与物理输入保留。

固定起点 `c21a6a981830c4a2aea7cebb46f38fd338200ba8`，并组合 084 的容器/EOF 解析修正 `cb54a96f3edeea86e16f1b42db669fd776f23146`。本任务把图片 owner 从 Native Markdown scanner 收回实际编辑器 accepted 语义投影，并贯通 Bridge、descriptor、首存、Save As 与 080 recovery handoff；不修改 079 cache、084 ledger 词法、依赖、lockfile 或 entitlement。

## 契约

1. 编辑器在同一稳定 runtime 捕获 `{ raw, imageURIs }`，Bridge 再绑定当前 `(documentID, revision)`。`snapshotReady.imageOwnership` 是 v1 可选兼容扩展；图片资源流程必须要求 proof，缺失不等价于已证明空数组。
2. owner URI 来自 accepted `EditorState.doc`，按文档顺序保留重复使用。first-wins reference、escape/entity、平衡括号、容器 code/math/保护块均复用实际生产 parser；Native 不再对 live raw 建立第二语法真值。
3. descriptor 注册、授权回填和 `prepareImageSave` 固定到 proof 版本。旧文档、旧 revision、跨 load/epoch、授权等待期间的新编辑与迟到 composition 均在资源变化前拒绝。
4. 首存只发布当前 proof 仍拥有的 accepted 草稿；已删除但仍在恢复区的 accepted asset 保留给 Undo/恢复，不成为本次 rewrite 或发布条件。重写后重新取正式 snapshot，并以 proof 验证 from 已消失、to 已存在。
5. Save As 只迁移 proof 中当前拥有的相对资源，Markdown 原字节不改。已证明 `imageURIs: []` 可跳过图片 source/target 目录授权并继续正式 Markdown safe-save；缺 proof 必须失败。
6. 080 handoff 必须在写恢复草稿后，用同一 document/revision/raw proof 确认 asset URI，随后才允许 `handedOff/accepted`。失败保留 intent、manifest、草稿和资源字节。
7. bare-CR 只读 runtime 以同一生产 canonical parser 解析 LF 语义副本，仅用于 owner；snapshot/proof raw 仍是原始 CR 字符串，不新增第二份 raw 权威。

## 安全与验收边界

- Native 继续负责真实目录 grant、安全 open、MIME/ImageIO decode、SHA-256、staging/publish/journal 与 `NSDocument` safe-save。
- Hostless XCTest 通过注入图片保存目录授权器计数，证明纯文本 Save As 不请求图片目录；这不是 OS 授权证据。
- 自动覆盖 Web production runtime/main、Bridge 双侧、NSDocument/store/migration/recovery 接缝、字节与 SHA 强断言。
- 不启动 App、窗口、`NSAlert`、系统面板、XCUITest、浏览器、CUA、bench-full 或物理输入。真实 Sandbox/bookmark、WK 图片、保存面板取消、物理 IME/键盘/AX 与关闭重开由管理者集中验收。
