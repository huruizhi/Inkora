# INK-M1-056：表格与任务列表集成验收

基线为 PR71 受检提交 `93a3b5933b8ca2ae221681bb5afc480e83bb247d`。在独立分支 `task/INK-M1-056-tables-tasks-integration` 通过 merge `f7d1ac9` 接回生产候选 `eb703563ea1e7367e5446a1ff62a021600114804`，保留原文权威、049/051 composition 最终发布、代码高亮和导航。未改依赖、锁文件、冻结样稿、Swift 或 Bridge 字段。

## 完成内容

- 生产 schema/parser、ledger、局部事务、runtime/main 与 NodeView 接入真实 GFM 表格和任务列表。涵盖单元格编辑、行列/对齐/删除表格、Tab 导航、新建表格、checkbox、任务 Enter/退出及内容统计。
- 管理者先独立运行组合基线：24 文件、451 测试通过；随后增加真实 `HTMLInputElement.click()` 与有 `isComposing` 标记的键盘反例，发现原候选未覆盖的交互边界。
- 正常 checkbox 点击不再取消默认激活，避免浏览器在同步 PM 更新后回滚 checked 显示；组合期取消激活时不在监听器里重复重置 checked。拒绝事务后控件恢复已接受的 PM 状态。
- 原 single-patch 逻辑错误地将任意补丁末端绑定到正文选区。checkbox 的语法字符因此污染 label 光标，第二次切换被拒。现在只有文字 replace 或规划器明确证明的 sourceCaret 才添加该锚点；输入规则显式返回其原文位置，保留水平线、保护片段前编辑等已有路径。
- checkbox Space、表格 Tab 在事件自身 `isComposing` 为 true 时不消费按键、不导航、不改文档。已有 session/view composition 守卫保留。

## 诊断与真实验证

单变量试验先排除旧节点引用：失败时 checkbox 仍 `isConnected=true`，重新查询 live DOM 仍与 raw 不一致。仅移除 click 默认取消后首次显示正确，但第二次切换报“任务 checkbox 原文标记无法定位”，投影显示正文 visual 3 被绑定到语法 raw 4；进一步收窄 caret 依据后连续切换通过。新增组合点击反例另证实“取消激活前手工重置”会发生二次反转。原始红日志保留于同名 evidence 目录，临时代码诊断已删除。
