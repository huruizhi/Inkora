## 本任务补正

- 基本写作命令统一进入局部原文补丁契约：strong、em、strike、code、link 的添加/移除，paragraph/heading、引用、列表、代码块转换，以及列表 Enter/indent/outdent 均在接受前重解析并核对派生投影；不使用整篇 serializer。
- 标题、引用、列表、代码围栏、分隔线与行内格式输入规则保留用户实际键入的原文字节；未闭合代码围栏按 CommonMark 合法 EOF 结束处理，不凭空补 closing fence。
- DOM composition 与 ProseMirror `composition` meta 共用逻辑会话 revision。end 前或 end 后到达的最终事务、连续会话、选区替换与 no-op 均按一个历史/发布单元收口；自动化证据明确为 synthetic，不替代物理输入法。
- `markSaved` 先校验 requestID、documentID 与 revision，再更新 runtime 保存点；错误或重复收据没有正文、dirty、history 副作用，合法旧 snapshot 收据仍保留较新编辑的 dirty。
- 未知自定义容器以带 issue 的逐字节不透明块与普通正文混排，阻断不安全 snapshot 并保留源码修复入口；删除吞掉任意构造错误的旧整篇 source fallback。
- source no-op 取消会保存当前有向选区并跨模式恢复；dirty 草稿取消仍回到可信文档选区，不携带草稿中的不可映射 selection，也不制造 revision/history。

## 任务边界

- 不包含表格/任务 checkbox/图片直接编辑、完整可视查找替换、代码高亮和 textarea 滚动 reveal；分别由既定后续切片或并行任务处理。
- jsdom 只证明事务、DOM 与 Bridge 接缝的确定性行为；真实 WKWebView、搜狗/系统拼音候选窗、caret 视觉位置、原生保存/关闭/重开仍需管理者验收。
- V1 仍是阶段性纵向切片；本补正不代表 Typora 对齐或 Inkora 1.0 全部能力完成。
