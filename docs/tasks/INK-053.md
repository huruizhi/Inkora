# INK-053：不支持的编码以只读错误状态打开（ENC-002）

- 来源：GitHub Issue #53
- 分支：`task/INK-053-unsupported-encoding-readonly`
- 规范：`docs/markdown-support.md` `ENC-002` / `SYN-U004` / `F-ENC-003`；实现位置见 `docs/text-format.md`、`docs/file-state.md`

## 交付范围

- UTF-16（LE/BE）、UTF-32（LE/BE BOM）与非法 UTF-8（含 GBK）不再使 NSDocument 打开失败，而是打开**只读错误状态**窗口：
  - 复用 INK-020 文件状态管道：新增 `DocumentFileState.unsupportedEncoding` 驱动窗口副标题，保存校验（`validateOriginalForSaving`）在同一闸门拒绝；
  - 窗口正文为 `EditorEncodingErrorView`：显示检测到的编码/错误类型（`InkoraDocumentError` 的 reason）与转换建议；不创建 WKWebView，无任何可编辑面，正文永不解码显示；
  - Save / Save As / `data(ofType:)` / `write(to:)` 一律抛出对应 `InkoraDocumentError`，原字节永不写回，也不把空缓冲或乱码写到任何位置；
  - dirty 恒为 false（无编辑器会话、`refreshFileState` 早退不强制 dirty），关闭走 `prepareForClose` 直通，不弹保存确认；
  - 不产生崩溃恢复草稿（`scheduleRecovery` / `captureRecovery` 的 dirty 闸门天然拦截）；
  - **最近文件策略（已选“不进入最近文件”）**：`read(from:)` 不记录 `DocumentOpenHistory` 与 `RecentDocumentNoter`；AppKit 在 `makeWindowControllers` 之前自动把 URL 记入 Open Recent（已用独立进程实证该时序），错误状态文档在 `makeWindowControllers` 中立即撤销该条目（`RecentDocumentNoter.withdrawDocumentOpened`，URL 按 realpath 规范化匹配 `/private/...` 形式）；`AppDelegate.openDocumentFromURL`（最近菜单/重启恢复路径）对错误状态打开不再二次记录。副作用：重启恢复不会重开只读错误窗口。
- 方案选择理由：只读错误状态是规范 `ENC-002` 的原义（“保留原始字节，文档以只读错误状态打开，并要求用户显式转换”），且 INK-020 的文件状态/副标题/保存闸门机制可直接复用，实现风险低于修订已冻结的规范。

## 非范围

- 转码支持（GBK / UTF-16 → UTF-8 转换 UI）；bare CR 只读（#54，`EOL-003`）；CRLF 结构化编辑（#52）。
- 只读错误窗口不提供“外部已转换为 UTF-8”的自动重载；用户转换文件后需关闭并重新打开（见 `docs/text-format.md` 已知边界）。

## 测试

- XCTest（`InkoraDocumentTests` / `RecentFilesRestoreTests`）：UTF-16 LE/BE、UTF-32、非法 UTF-8（GBK）打开后的只读错误状态（原因、无乱码、不 dirty）；Save/Save As/`data(ofType:)`/`write(to:)` 全部拒绝且原字节不变；窗口副标题与错误视图、无编辑器面；不产生恢复草稿；不更新最后打开记录；撤销最近条目的 realpath 匹配。
- XCUITest（`DocumentOpenUITests`）：非法 UTF-8 打开只读错误窗口且无编辑器；UTF-16 打开 → 错误提示 → Cmd+S 报错且文件字节不变 → 关闭无保存确认 → 不出现在 Open Recent。UI 测试由 CI 执行。

## 原有断言修改（行为变更逐条说明）

1. `testInvalidUTF8IsRejected` → `testInvalidUTF8OpensInReadOnlyErrorState`：`read` 不再抛错，改为断言只读错误状态与空文本。
2. `testGBKEncodedFileIsRejectedAsInvalidUTF8` → `testGBKEncodedFileOpensReadOnlyAsInvalidUTF8`：`InkoraDocument(contentsOf:)` 不再抛错，改为断言错误状态、原字节不变、不 dirty。
3. `testUTF16AndUTF32ByteOrderMarksAreRejectedWithExplicitErrors` → `testUTF16AndUTF32OpenReadOnlyWithExplicitReasons`：同样从抛错断言改为状态断言，原因匹配保持不变。
4. `testInvalidUTF8FileDoesNotCreateAnEditableDocument` → `testUnsupportedEncodingDocumentCannotSaveAnywhere`：不可编辑的意图扩展为“不可保存到任何位置”（Save/Save As/直接写盘全拒绝），并验证关闭准备不失败。
5. `RecentFilesRestoreTests.testFailedURLReadDoesNotReplaceLastOpenedDocument` → `testEncodingErrorURLReadDoesNotReplaceLastOpenedDocument`：读取不再抛错，“最后打开记录不被替换”的意图保持。
6. `DocumentOpenUITests.testInvalidUTF8ShowsAnErrorWithoutOpeningADocumentWindow` → `testInvalidUTF8OpensAReadOnlyErrorWindowWithoutAnEditor`：按新行为断言只读错误窗口。
