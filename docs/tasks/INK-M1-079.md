## 根因与实现

V8 profile 支持排序假设：最大热点是每 link owner 对完整 span/expectation 表重复
`filter/map`，其后是每 source range 对完整 markdown-it token 表重复扫描；同一不可变
raw/PM/projection 上的 `saveEligible`、选区映射和 snapshot 又重复建立 context。修复保持完整
证明链，不放宽 `doc.eq`、owner 或原文断言：

- 一次建立 owner、reference usage、definition 与 label source interval 索引，仍逐 owner 校验
  PM mark、嵌套图片和精确 source/visual 范围；
- 一次把 relevant markdown-it token 按 source overlap 分配给 range，保留 BOM overlap、
  容器内 table、code 和原 token 顺序；
- context 缓存严格绑定完整 raw 值、PM doc 对象和不可变 projection 对象；selection anchor、
  provenance、source apply、拒绝恢复、Undo/Redo、reopen 和新 raw 都会换 key；
- 字素边界索引只绑定完整 raw 值，CRLF、surrogate、ZWJ/combining 边界仍由原规则拒绝；
  折叠 source/visual 端点只执行一次同参数映射；
- opt-in WK 测量入口先删除旧 `webview.json`，避免不同子集运行的残留指标混入当前证据。

公共行为回归覆盖索引下同 href 多 owner、共享 reference、嵌套链接图片、反向选区、完整
raw、snapshot、dirty/revision/history/saveEligible，以及缓存跨 source cancel/apply、Undo/Redo、
同文 reopen、Unicode/CRLF 非法边界和 managed image owner rewrite 的失效。没有通过内部命中
计数断言实现。

source no-op 60.59ms；large/large-crlf 输入为 1245.51/1246.57ms，snapshot 为
178.96/184.24ms。这里的 p95 仅是少量样本顺序统计，不是跨设备 SLA。

完整原始样本、输入 SHA、源码或 bundle resource SHA 在
`docs/evidence/INK-M1-079/`。model JSON 的 `commit` 是测量时固定父 HEAD；其中 `sources`
