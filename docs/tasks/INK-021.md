# INK-021：崩溃恢复草稿与恢复流程

- 来源：GitHub Issue #21
- 分支：`task/INK-021-crash-recovery`
- 基于已合并的 INK-020（`2aceb36`）
- 状态机与选择：[崩溃恢复草稿](../recovery.md)

独立 sandbox 草稿存储、原子写入、1 秒 debounce 与内容去重；记录 revision、源 URL/bookmark、源指纹、原始正文 SHA-256、BOM/换行和版本信息。启动校验后选择恢复/放弃/另存；恢复为未命名 dirty 副本，源文件变化使用 INK-020 冲突文案。保存、关闭/放弃和正常退出清理；删除失败由持久化凭据抑制旧草稿，凭据失败可退回删除。

后台 snapshot 不移动焦点或强制结束 composition。保存/重载/关闭使旧请求失效，恢复初始化不会误清 dirty。所有 UI/烟测使用隔离 session，Hostless XCTest 使用临时目录。

测试覆盖重启状态、命名/未命名/BOM/混合换行、截断/非法 JSON/正文哈希不符、源文件改写/删除/已保存字节、删除与写盘失败、内容去重、debounce、保存和正常关闭清理、迟到 snapshot 及 IME composition。新增 XCUITest 真实编辑落盘后异常退出，再启动发现草稿、恢复并验证原文件未改。

非范围：NSDocument 就地自动保存、版本历史、自动合并。真实 IME 与存储硬件同时拒绝全部写入/删除的故障仍有人工验收及持久化边界，见恢复文档。

## 本地验证

`make lint test-editor test-bridge test-native test-ci` 通过：编辑器 94 项、Bridge TypeScript 11 项、Bridge Swift 7 项。补充保存失败保留草稿用例后再跑 `make lint test-native`，76 项 XCTest 全过、0 skipped。本地未运行 UI 测试或启动 App，XCUITest 与 Debug/Release 烟测交给 CI。

补充 Web Content 进程重放同 revision 未保存 snapshot 的回归：先实测 dirty/草稿保留断言失败，再增加 native dirty 保护；重载测试明确等待新的 Web 页面，不依赖重载前后相同文本。

真实 Bridge 自动落盘回归覆盖 queryState 回传不应重置 debounce/epoch，并覆盖源文件删除后未修改缓冲区的恢复采集。
