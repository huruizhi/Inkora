# INK-M1-084：容器代码与续段原文定位

固定起点 `c21a6a981830c4a2aea7cebb46f38fd338200ba8`。082 已证实引用代码围栏与列表续段图片的 PM 语义正确，但账本拒绝保存；本任务修正位置依据，不更改图片 Bridge 或资源授权。

## 诊断与改动

1. 最小公共 `SourceAuthoritySession` 回归先红：引用中的 tilde 围栏无法保存。三个排序假设为容器 code token 遗漏、容器前缀缺少解析时依据、parser/PM 结构不相等。
2. 前两项成立。原账本在容器内只执行 inline/table token；现按同一源码 token 顺序加入实际 PM code 节点，并保留逐字符和 CRLF 归属。markdown-it block rule 接受 token 时记录尚未恢复的 list/quote 缩进列，映射时使用该 provenance，不根据重复正文首次匹配推测容器起点。
3. EOF 追加回归另行先红：`[ref]: real.png\n\n- ~~~md\n  value` 的 PM code 内容为 `value\n`，源码中不存在该末尾 LF。根因是向每个原文切片追加空行与引用定义；现用 parser 环境传入既有受支持定义子集，解析输入只保留实际切片。没有扩大多行定义支持或放宽 `doc.eq`。
4. 079 的 token/range 与 owner 索引、raw/doc/projection 缓存保持。新增元数据依赖锁定 markdown-it 14.3.3 block rule roster 及缩进字段；升级依赖必须复核。部分 tab 列展开仍明确拒绝，不创造原文字符边界。
