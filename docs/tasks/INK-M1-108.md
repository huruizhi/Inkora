## 缺口与范围

首阶段 03/07 要求同一篇技术文章经过直接编辑、工具操作、保存迁移和重开。既有 `EditorWebViewTests` 已有 PNG 实际资源通道与 Bridge 字节保存测试；`LocalImageStoreTests` 已有四格式 ImageIO 解码；`InkoraDocumentTests` 已有注入 snapshot 的资源迁移。不能仅凭这些分开结果声称四格式与最新保护投影的组合闭环已观察。

本任务仅增加真实生产组合验证，不改产品代码、依赖、Bridge、规范或既有测试。使用已约定的公开接缝：真实 WK DOM 编辑/按钮 → EditorView/运行时 → Bridge snapshot/owner proof → NSDocument 保存 → 新文档与新 WK 重开。仅注入系统目录选择边界及现有公开 snapshotRequester；其返回值来自实际 controller，不伪造 snapshot。全部文档和资源位于唯一临时目录，WebView 无 window，不调用 makeWindowControllers、不启动 App/面板。

## 单一场景与独立预期

`WritingLifecycleTests.testMixedArticleEditsMigrateFourImageFormatsAndReopenWithExactBytes`：

1. BOM + CRLF、无尾换行技术文章同时包含中文/ZWJ/组合重音、元数据、标题、任务、表格、围栏代码、链接、Wiki、callout、脚注及四种本地图片。
2. PNG/GIF/WebP 使用已有生产测试的字节 fixture，JPEG 由同 PNG 经 ImageIO 编码。四种图片均经实际 capability/资源 handler/NodeView 加载，校验 complete 与 naturalWidth/Height；不只检查 ImageIO。
3. DOM 选区普通插入；点击任务 checkbox；语言选择器改为 python；直接编辑单元格；真实查找面板将普通正文中的“原文”替换为“正文”。保护预览中的同文不参与查询，也不产生伪图片 owner。
4. 替换 Undo/Redo；源码 no-op 往返不改变 raw/revision；通过实际 controller 的 owner proof 执行 Save As 到另一目录。
5. 独立预期从固定文章字面和明确允许的局部改动推导。原 Markdown 与图片不变；新 Markdown 精确等于 BOM + 预期 CRLF 原文；四张图片与源文件逐字节一致；保护注释中的 missing.png 不被迁移。
6. 新 NSDocument/新 WebView 重开目标，重新加载四格式图片，检查真实任务/表格/语言/正文链接、完整 snapshot 和 image owner 集合，且 clean、无跨重开 Undo。
