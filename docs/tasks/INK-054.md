# INK-054：bare CR 整篇只读与显式 LF 转换

- 来源：GitHub Issue #54（EOL-003）
- 分支：`task/INK-054-bare-cr-readonly`

## 实现与选择

- 复用 INK-052 `classifyLineEndings` 的 `bare_cr` 路由，先于语法安全/源码编辑分支返回只读 textarea runtime；snapshot 持有原始字符串，不受 textarea 的 LF 归一化影响。只读状态没有编辑监听或历史，dirty / canUndo / canRedo 恒为 false。
- 原生保存层按相同 CR 后无 LF 规则防守（扫描 UTF-8，避免 Swift Character 将 CRLF 合为一个字符），新增 `DocumentFileState.bareCR`，复用文件状态副标题。Save、Save As、data 和 write 全部拒绝；编辑器通知不能使原生 dirty；关闭无需 snapshot；恢复调度、捕获、写入三个入口均拒绝只读草稿。
- 原生说明文字与 `ConvertBareCRToLF` 按钮提供显式转换；Command-Option-L 可直接操作，按钮有 accessibility identifier 与帮助文字。
- 选择整篇统一为 LF：规则简单且无混合风格/平票歧义，与规范 F-EOL-004 golden 一致。保持 BOM、Unicode、末尾边界数量，不写磁盘。转换立即 dirty，正常 Save 或 Save As 成功后才清除。
- **转换本身不可撤销**（界面明确说明）：现有 Bridge history 是单会话正文历史，没有跨会话格式变更事务。重新建立 document ID 与历史基线，避免 Undo 后原生写盘权限和 Web 编辑权限不同步；原文件直到用户保存前不变。后续正文编辑可正常 Undo/Redo，回到转换基线仍 dirty。
- **进入最近文件**：与 INK-053 无法解码的错误窗口不同，bare CR 正文可读且能显式转换，视为成功打开；保留 Open Recent 与最后打开记录。
- 不增加依赖，不改变正常 LF / CRLF / 混合 LF+CRLF 的路由或 IME 内核。

## 测试与断言变更

- 共享 fixtures：`bare-cr{,-lf,-crlf}.{input,expected}.md`，含 CJK、NFD、ZWJ emoji、末尾换行/无末尾换行；`.gitattributes` 禁止文本归一化。
- Vitest：三个只读 golden（含伪造 input 后原始 snapshot 不变、dirty 恒 false、无 Undo/Redo）；转换后的 LF golden 可编辑、Undo/Redo 保真。
- XCTest：三个输入 × 有/无 BOM，检查只读状态、拒绝所有保存路径、原字节不变、无草稿、转换逐字节结果、dirty 与显式 Save As；真实 WKWebView 检查只读路由、转换按钮元数据、转换后编辑及 Undo/Redo。
- XCUITest 新增 `DocumentOpenUITests.testBareCRReadOnlyConvertsWithKeyboardWithoutSaving`，**UI 未验证**。同时受影响的既有测试：`testFileMenuExposesSaveAndSaveAsCommands`、`testUndoRedoMenusAndShortcutsWhileWebEditorHasFocus`（历史菜单/快捷键类场景）；发布前验证只读窗口键盘与 AX、Save/Save As、关闭与最近文件。

原有断言按 EOL-003 调整，未删除或跳过测试：

1. Vitest `keeps a bare-CR document byte-identical through an edit in source mode` 改为三个只读 golden：原先期望 bare CR 可编辑且插入 CR，现在输入被拒绝、原文不变；转换后编辑历史另行验证。
2. `InkoraDocumentTests.testUnmodifiedMarkdownRoundTripsByteForByte` 的 `mixed-eol` 含 bare CR：原先 data 写回成功改为明确拒绝，同时保留原文逐字节断言。其余 fixture 保存断言不变。
3. `EditorWebViewTests.testUnmodifiedMarkdownSavesThroughBridgeByteForByte` 的 `mixed-eol`：改为 Bridge snapshot 逐字节一致且 data 保存拒绝。其余 fixture 的实际写盘逐字节断言不变。
4. `testMixedAndBareCRRemainInSourceMode` 保留源码与 snapshot 断言，新增 bare CR 只读、纯 LF/CRLF 混合仍可编辑断言。
