# INK-019：最近文件、Finder 文件关联与重启恢复

- 来源：GitHub Issue #19
- 分支：`task/INK-019-recent-files-restore`
- 依赖：NSDocument 打开/保存（INK-015）、原生菜单（INK-017）

## 交付范围

- File > Open Recent 子菜单：列表由 NSDocumentController 管理（`recentDocumentURLs` / `noteNewRecentDocumentURL` / `clearRecentDocuments`），含 Clear Menu；
- 打开文件后进入最近列表（odoc / Open 面板 / Open Recent / 恢复打开均会记录）；
- Finder / Dock 打开 `.md`：冷启动与运行中均复用 NSDocumentController 标准打开流程；
- 重启恢复：只恢复上次成功打开的文档，窗口位置通过 NSWindow frame autosave 恢复；
- App Sandbox 下用 app-scoped security-scoped bookmark 保持恢复访问权限（使用 main 已有的 `com.apple.security.files.bookmarks.app-scope` entitlement）；
- 失效路径：Open Recent 中已不存在的文件点击后弹出明确提示并从列表移除；恢复路径文件失效时静默清理并回退 Untitled，均不崩溃、不弹空文档窗口。

## 非范围

- 目录树、多标签页、iCloud、外部文件变更监控（INK-020）、dirty 关闭确认（INK-018）。

## 实现要点

- `RecentDocumentList.swift`：`RecentDocumentListManaging` 协议封装 NSDocumentController 最近列表（单元测试不触碰真实共享列表）；单条删除用 clear + 逆序 re-note 保序实现；`isMissingFileError` 按 Cocoa 错误码（260 / 256+POSIX ENOENT）分类。
- `OpenRecentMenuController.swift`：NSMenuDelegate 驱动的子菜单构建；菜单项用控制器自有 selector，避免 AppKit nib 时代的自动填充与重建竞争；文件缺失时 NSAlert 提示并从列表移除，其他读取错误走 `NSApp.presentError`。
- `DocumentOpenHistory.swift`：最后成功文档的 app-scoped bookmark 存取（scoped 失败回退普通 bookmark，覆盖容器内路径）；stale bookmark 解析后自动刷新（文件移动可继续恢复）；`RecentDocumentNoter` / `DocumentOpenHistory.shared` 在 AppDelegate 的 willFinishLaunching 配置前保持惰性，单测实例化的文档不会写任何真实偏好；`LaunchDefaultsResolver` 支持 `-INKTestDefaultsSuite` 注入隔离 defaults。
- `LastDocumentRestoreController.swift`：`applicationShouldOpenUntitledFile` 中决策——有可达的上次文档则恢复并返回 false（跳过 Untitled）；文件缺失静默清理回退 Untitled；文件存在但读取失败（如非 UTF-8）呈现一次错误后回退 Untitled；恢复不会触发任何保存或覆盖。
- `InkoraDocument`：`read(from:ofType:)` 成功后记录历史（NSDocument 在主线程读取，用 `MainActor.assumeIsolated` 桥接 SDK 非隔离覆写上下文）；`makeWindowControllers` 设置 按文档 URL 区分的 `frameAutosaveName`（避免与 Untitled 或其他文档冲突）、`isRestorable = false`——关闭 AppKit 自动窗口状态恢复，避免"恢复所有退出时窗口"与本任务"只恢复上次成功打开的文档"策略冲突及 odoc 冷启动双开竞争；窗口几何仍经 frame autosave 跨启动保留。
- `Info.plist`：`net.daringfireball.markdown` 在 macOS 14 SDK 中为系统声明 UTI（本机已验证 `UTType(filenameExtension: "md")` 解析到该标识符），现有 CFBundleDocumentTypes 声明足够，无需 UTImportedTypeDeclarations；`LSHandlerRank` 保持 Alternate，不抢占用户默认编辑器。
- 测试隔离：三个 UI 入口使用独立 bundle ID `com.huruizhi.Inkora.UITesting`，隔离系统最近列表、Sandbox 容器和窗口偏好；UI 测试全部通过 `-INKTestDefaultsSuite`（每次启动独立 suite）隔离恢复状态与偏好；既有 `DocumentOpenUITests.launchApplication` 同步加了该参数。NSDocumentController 最近列表按测试 bundle ID 隔离，Clear Menu 不再影响用户真实 App 的列表；冷启动 Launch Services 也传入隔离 suite。
