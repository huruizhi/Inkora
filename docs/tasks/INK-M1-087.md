固定起点 `d6c159bb2524a979c9ef95fc9cc3a5a5b2d0af14`，分支 `task/INK-M1-087-reference-definition-coverage`。问题来自既有 `SYN-S010` 实现缺口，不归因于083统一图片所有权。没有恢复 Native Markdown scanner 或增加第二份内容权威。

## 真实红例与诊断

公共 `SourceAuthoritySession` 打开 `[go][ref]\r\n\r\n[ref]:\r\n  <docs/a(b).md>\r\n  "中文 &amp; title"\r\n` 抛出「尾部存在无法归属的原文范围」。合法的转义括号/跨行图片引用 label 也无法打开。

排序假设：① gap 只接受一行定义；②定义语义被单行过滤丢弃；③账本字段仍依赖单行正则。单变量验证结果依次是：仅按接受范围遮蔽 gap 后不再抛错，但正文变成字面 `[go][ref]`；消费 parser 定义语义后正文正确，保存资格仍失败；加入实际字段 provenance 后语义、账本与局部编辑同时通过。原始日志以无损 JSON 包装保存于[证据目录](../evidence/INK-M1-087/)，记录原日志 SHA，避免日志自身 CRLF 触发补丁空白检查。

在起点代码上原样重放新36项引用回归，实际19 failed / 17 passed；恢复实现后转绿。另一个真实 main 表单红例：未修改的多行 title 经单行 input 丢失换行，点击更新后 revision 从0变1；修复后 no-op 保持0，随后只改 href 保留 title 原字节。BOM+CRLF扩展样例又暴露「BOM占用一个缩进空格」：官方例193多出空段落；现解析副本排除 BOM，原文坐标显式加回，不让 BOM 参与缩进计数。

## 实现与公共边界

- `reference-context.ts` 在锁定 markdown-it 的 reference rule 接受时，记录实际 container indentation 下的 label、destination、完整 destination token、title 及全定义行范围。字段语义复用其 destination/title helper；按 parser 的规范化坐标映射回原始 UTF-16/BOM/CRLF。
- `source-document.ts` 只把被接受的定义传入全局 first-wins env，按其物理行范围判断 gap；不向块源码追加伪定义/空行，不使用第二套定义语法。
- `source-ledger.ts` 消费同一 provenance，保留隐藏语法范围与分开的 href/title 字段；容器、代码内伪定义、重复定义与保护块安全规则继续由生产 parser/投影验证约束。
- 链接属性更新只补改动字段；语义 no-op 不规范化转义或实体。angle destination 后添加/移除 title 不删除 `>`。单行表单展示多行 title 的空格副本，未编辑字段仍提交原语义值。
- 空 destination（例如 `[ref]: <>`）是 CommonMark 合法值，schema/DOM/JSON 可表示并精确往返；图片空 href 不成为本地资源 owner。旧「空字符串即无效 JSON」断言调整为真实的非字符串42负例，同时新增空值 JSON 往返；创建链接和图片导入的危险 URL/非空守卫未删除。
- 083测试中把合法跨行 label 固定为 `toThrow` 的临时限制改成可保存且图片 URI 正确的正例。没有删掉该场景或放宽 `doc.eq`。085/086缓存及新 caret/旧 anchor 验证保持。
