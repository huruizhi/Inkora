# INK-052：CRLF 文档支持结构化编辑并保留换行

- 来源：GitHub Issue #52
- 分支：`task/INK-052-crlf-structured-editing`

## 实现与规则

- 独立换行分类：LF、纯 CRLF、混合 LF/CRLF、bare CR；后两者保持源码模式，bare CR 的只读与显式转换留给 #54。
- 纯 CRLF 安全文档进入结构化模式前归一化到 LF；快照序列化后整篇恢复 CRLF，包括代码块内部和新增边界。未修改直接返回原文；保留基线全部尾部换行。
- CRLF 输入若 codec 往返会改写其他空白，仍走源码模式，避免局部编辑引入无关 diff。表格、HTML 等未建模结构继续走源码模式，原始内容由源码内核保留。
- 保存确认的文本同样归一化后建立 ProseMirror dirty 基线；Bridge revision、snapshot 与 save barrier 协议不变。原生 BOM 读取和写盘逻辑不变，避免与 INK-053 的读取路径修改冲突。
- WKWebView golden 测试发现段落 DOM 回读将软换行变为空格；paragraph / heading 指定 `whitespace: "pre"`，使 ProseMirror 按完整空白回读，防止局部编辑破坏其他换行。

## 测试与 fixtures

- `tests/fixtures/crlf-structured{,-final}.{input,expected}.md`：共享字节 golden，覆盖无尾部换行、尾部空行、软换行、围栏代码、列表、中文、组合字符和 emoji；`.gitattributes` 禁止换行转换。
- Vitest：结构化原样快照、局部编辑 golden、保存基线、旧保存确认后的新编辑、Undo/Redo、composition、代码内新增换行、混合/bare CR 路由、HTML/表格源码保真、非稳定 codec 输入回退。
- XCTest / WKWebView：真实 DOM 局部编辑、精确 snapshot golden、带/不带 BOM 的保存字节验证，混合/bare CR 源码路由。原生文件保存仍走现有原子写入路径。

## INK-022 断言变更

- `editor-runtime.test.ts` 的 `routes documents containing CR to source mode even when structurally safe` 改为混合 / bare CR 参数化断言：原先要求纯 CRLF 进入源码模式，与 #52 的新规则冲突。纯 CRLF 的结构化断言由新增 golden 测试覆盖，原文精确相等断言保留。
- `testEditedSnapshotKeepsCRLFLineEndingsAndUnicode` 保持原断言：其输入缺少块间空行，codec 往返会额外规范化，因此仍回退源码模式。
- 未删除、跳过或放宽已有测试。
