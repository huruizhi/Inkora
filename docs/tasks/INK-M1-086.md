# INK-M1-086：字素扩展后旧锚点的失效处理

独立起点 `cb54a96f3edeea86e16f1b42db669fd776f23146`；实现提交 `25370d9`，与085组合提交 `4991cb7`。本问题是在085边界优化验证中发现，固定起点已经存在，不归因于按需 Unicode 查询。

## 红例与根因

公共 SourceAuthoritySession 打开 `AeZ\r\n`，在 e 后输入单独 U+0301。候选是合法且未规范化的 `Ae\u0301Z\r\n`，但旧 raw/visual 插入锚点按左侧 affinity 映射到合并后的 e+重音内部，接受过程以「投影 anchor 映射失败：grapheme 内部不是合法边界」拒绝。

排序假设：旧锚点已被新字素消耗；局部原文补丁错误；或 parser/PM 投影不相等。实际原文与 PM 相等，重新打开候选也合法；首个失败是旧锚点检查。无源码 serializer、Unicode normalization 或非法字符过滤参与修复。

## 限定修复

- 只有旧锚点的 raw 与 visual 都严格位于同一条可视字素 span 内，且当前原文解析与目标 PM 完全相等时，才淘汰该已不存在的旧边界。
- BOM、CRLF、代理对及越界检查单独保留；不根据诊断字符串分支，不创建假 boundary Set。
- 新 caret 锚点不参与淘汰，仍须完整验证。新 caret 本身落入合并 emoji 内部时拒绝并保留完整候选，作者可通过主动源码在明确合法位置提交。
- 原历史快照保留，Undo/Redo 恢复原始字节、选区与保存点；两个 synthetic composition 更新仍只形成一个逻辑历史单元。
