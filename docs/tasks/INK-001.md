# INK-001：工程骨架（AppKit 外壳 + WKWebView 宿主 + 编辑器前端脚手架）

- 执行：Codex / gpt-5.6-sol（Tier 1：决定后续所有模块的工程结构）
- 分支：`task/INK-001-skeleton`（在 `.worktrees/INK-001` worktree 中工作）
- 依赖：无（ADR-0001 已接受）
- 后续依赖本任务：INK-002a（CodeMirror 6 原型）、INK-002b（ProseMirror/Milkdown 原型）

## 目标与背景
为 Inkora 建立最小可运行的工程骨架，使后续两个编辑内核原型可以并行接入同一个原生宿主，在真实 WKWebView 中验证中文输入法与文件保真。先阅读 `AGENTS.md` 与 `docs/adr/0001-tech-stack.md`。

## 范围
1. **原生 App（`app/`）**
   - AppKit、Swift 6、macOS 14 deployment target、启用 App Sandbox，entitlement 仅 `com.apple.security.files.user-selected.read-write`。
   - 基于 `NSDocument` 的文档型 App：支持打开/新建/保存 `.md`（UTType `net.daringfireball.markdown`）。
   - 窗口内容为 `WKWebView`，从 App Bundle 内加载编辑器静态资源（不访问网络，使用 `loadFileURL` 或自定义 URL scheme，二选一并在 ADR 中说明）。
   - **桥接协议 v0**（`docs/bridge-protocol.md`）：至少包含 `load(text)`（Swift→JS）、`contentChanged`（JS→Swift，用于 dirty 状态）、`getText`（保存时取回全文）。保存内容必须以 JS 返回的原始字符串逐字节写回。
   - 工程生成方式由你选择（XcodeGen / 手写 xcodeproj / Tuist），需保证 `xcodebuild` 可命令行构建；若引入工具（如 `brew install xcodegen`），写入 `make setup` 并在 ADR 记录理由。
2. **编辑器前端（`editor/`）**
   - pnpm + Vite + TypeScript，构建产物输出到 App 可打包的位置。
   - 暂用 `<textarea>` 作为占位内核，实现桥接协议 v0；预留 `EditorKernel` 接口（`setText / getText / onChange / focus`），以便 INK-002a/b 替换实现。
3. **工具入口**：根目录 `Makefile`，提供 `setup / lint / test / run / build`。`lint` 至少含 `swift-format` 或 SwiftLint 之一（选已安装或易安装者）及 `tsc --noEmit`。
4. **测试**
   - Swift：XCTest 覆盖"读取 → 不修改 → 保存"逐字节一致（含 CRLF、无结尾换行、UTF-8 中文、emoji 的 fixture，放 `tests/fixtures/`）。
   - 前端：Vitest 覆盖桥接消息编解码。
5. **ADR-0003**：记录工程生成工具、资源加载方式、桥接方式的决策。

## 禁止范围
- 不实现任何 Markdown 渲染或 WYSIWYG 逻辑（属于 INK-002a/b）。
- 不引入 AI、网络、主题、导出相关代码。
- 不修改 `docs/adr/0001-tech-stack.md`、`AGENTS.md`。

## 验收标准
1. `make setup && make build` 在干净 checkout 上成功。
2. `make test` 全部通过（Swift + 前端）。
3. `make run` 启动 App，可打开 `tests/fixtures/` 中的中文 Markdown 文件，在 textarea 中用系统中文输入法输入，保存后内容正确；未修改时保存与原文件逐字节一致（提供 `cmp` 结果）。
4. App 以沙盒运行（`codesign -d --entitlements - <app>` 输出证据）。
5. 提供一张运行中的窗口截图（`screencapture` 保存到 `docs/evidence/INK-001/`）。
