## 产品闭环

1. 启动发现 pending 图片后提供「恢复图片草稿 / 稍后 / 放弃」。同 session 有正文草稿时逐字节恢复 BOM/EOL/正文；只有 manifest 时打开空白的未命名图片草稿，不虚构旧正文或旧选区。
2. 恢复文档显示常驻 banner。作者确认后重新查询当前 document/epoch/revision/directed selection，再走既有 `applyImageImport`；「稍后」只收起成仍可继续的入口。
3. schema 3 保留历史 `importIntent`，另记新 `recoveryIntent` 与 pending/confirming/handedOff 状态。Bridge 成功后必须取得真实 snapshot、验证真实图片 owner 并写入恢复草稿，最后才记 accepted。
4. 捕获、跨 epoch、Bridge、snapshot、manifest 或保存失败时保留原草稿、manifest 和图片字节。明确放弃先写 session/document/asset/SHA 回执，只删除所选会话的 pending 且无人引用资源，不删除同 session 已接受资源、未知文件或其他会话。
5. handoff 后继续复用既有首次保存路径事务、资源发布、`NSDocument` safe-save 和 plan receipt；成功目标的 Markdown 与图片 SHA 可重新读取一致，draft URI 不落盘。
