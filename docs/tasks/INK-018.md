# INK-018：dirty 状态与关闭决策

- 来源：GitHub Issue #18
- 分支：`task/INK-018-dirty-close`

编辑器 dirty 是唯一历史依据；原生层在 clean → dirty 时记一次 `.changeDone`，在 dirty → clean 时 `.changeCleared`。Undo、Redo 的 revision 仍单调递增；保存确认可以使用相同 revision。旧 revision 与其他文档状态均被忽略。NSDocument 自动同步窗口 edited 状态，不建立第二套原生 Undo 栈。

关闭按钮、Cmd+W、File > Close 共用 `canClose`；Cmd+Q 先准备所有文档，再调用 `reviewUnsavedDocuments`。准备阶段让原生 first responder 结束 IME，Web 端等待 compositionend 的最终 transaction，先回传状态再返回 snapshot。未能结束 composition 或取得 snapshot 时取消关闭并显示错误。真正的关闭确认、保存面板和放弃/取消行为由 AppKit 负责。

选择保存复用现有 FIFO revisioned snapshot safe-save；写入失败不会确认 baseline，也不会允许关闭。保存期间出现更高 revision 时原生 edited 状态保留，随后由编辑器确认准确 baseline。没有启用自动保存、草稿恢复或外部文件协调。

## 验证

- XCTest：dirty/clean 映射、Undo/Redo 和相同 revision 保存确认、过滤旧状态、原生计数不累加，以及既有保存失败测试。
- XCUITest：四个关闭入口分别验证取消保留、保存落盘和放弃；Debug writer 注入权限错误，验证保存失败后的窗口、文本和再次关闭提示。
