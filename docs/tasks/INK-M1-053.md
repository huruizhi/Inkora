# INK-M1-053：原文权威内核原生回归修复

- 状态：非 UI 完成候选，待管理者独立验收
- 固定基线：`744c0141f5ffb0c6fcb0b7c2d6761efbce0be973`
- 架构依据：ADR-0004、`docs/design/source-authority-production-v1.md`

## 本任务修复

- 将六项旧原生 WKWebView 回归迁到生产原文权威接缝：普通文档默认验证
  ProseMirror 可视投影，只有主动点击源码入口后才操作 textarea 草稿并显式提交。
- mixed EOL 继续进入可视模式并以 Bridge snapshot 保留精确原文；含 bare CR
  的文档仍使用只读 textarea，显式转换为 LF 后进入新的可编辑会话，转换边界不可撤销，
  后续源码编辑仍共享真实 Undo/Redo。
- CRLF 与 Unicode 编辑通过可视→源码→提交→snapshot 路径验证，保留文档既有
  CRLF 风格以及组合字符、emoji，不把渲染文本当原文。
- reload 以旧页面 token 消失和第二次 ready/load 后的 versioned snapshot 为证据；
  documentID、revision、原始尾 LF 均保持一致。DOM 出现后只对合法
  `editorNotReady` 短暂重试，不扩大 Bridge 请求超时。
- composition/recovery 测试在真实生产 ProseMirror DOM 与 Bridge 上做 synthetic
  事件重放：中间态不发布 revision、不生成 recovery、不 blur、不移动选区；稳定边界后
  只发布一次 revision，精确 raw、recovery 和一组 Undo/Redo 一致。
- 通用 WK 加载 helper 以成功 Bridge snapshot 判定会话 ready，不再用会丢失隐藏换行、
  尾 LF 和块边界的 `textContent` 充当原文 oracle。

## 诊断结论与边界

- 六项冻结红例均来自旧测试仍假设自动整篇 source textarea，或把 DOM 已出现等同于
  Bridge ready；正确生产接缝下没有发现需要修改 App/Editor 产品源码的缺陷。
- 自动 composition 仅证明 WKWebView 中生产 DOM/runtime/Bridge 的协议与历史边界，
  不冒充物理键盘或真实中文输入法验收。本任务未运行 XCUITest、未启动 App。
- 本候选不代表 V1、首阶段或 Typora 对齐整体通过；管理者仍需按上层计划独立验收。
