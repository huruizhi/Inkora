## 已完成

1. production runtime 的搜索结果新增按值捕获的 `runtimeBinding`，包含
   `documentID/revision/raw/load epoch`。`main` 在接受 `loadDocument` 后把当前文档身份与
   `loadEpoch` 显式交给新 runtime；可视导航和替换先核对结果所属 runtime load，再重搜
   当前内容。相同 documentID/revision/raw 的新 load、相同 epoch 的跨文档结果均原子拒绝；
   当前 runtime 的 JSON 值拷贝和稳定重复查询仍可使用。纯 `searchSource` 与源码 plan API
   不读取全局状态，SearchPanel 的既有 epoch/revision/current raw 复核继续保留。
2. source ledger 不再用“首次找到同字符串定界符”猜测 `*`/`_` 的 em/strong 归属。
   它通过锁定 `markdown-it@14.3.3` 的 inline ruler 接缝记录 CommonMark 已配对的原文
   delimiter 位置，再建立 ledger provenance。`**alpha *omega***`、下划线同形、em 外包
   strong 及相邻三字符 closing run 均恢复保存资格；跨 marks 替换按起点 marks 得到最小
   原文补丁。PM `doc.eq`、Unicode、owner 与候选重解析校验没有放宽；这不是完整
   CommonMark delimiter algebra 的声明。
