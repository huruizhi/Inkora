# INK-022：覆盖编码、换行符、Unicode 与格式边界

- 来源：GitHub Issue #22
- 分支：`task/INK-022-text-format-boundaries`
- 依赖：Markdown codec 与保真规则、INK-015 文件打开、INK-016 文档保存

## 交付范围

- UTF-8 BOM 策略：读取剥离、写盘恢复，未修改与编辑后保存均保留 BOM 有无；UTF-16/UTF-32 BOM 与非法 UTF-8（GBK 等）给出明确错误，绝不乱码保存；
- LF/CRLF/bare CR 处理：未修改保存逐字节一致；源码模式逐边界保留并按 EOL-002 继承新插入换行；含 CR 文档整体进入源码模式；
- 尾部换行：结构化模式编辑后按基线恢复，不自动添加或删除；
- Unicode：组合字符、NFC/NFD、emoji/ZWJ、变体选择符、CJK、RTL、零宽与全角空格不做任何归一化，fixtures 字节级锁定；
- 含特殊字符的路径/文件名（emoji、ZWJ、组合字符、CJK、空格）的打开、Save As 与重新读取；
- 策略与 fixture 映射文档化：`docs/text-format.md`；
- 跨编码、换行、Unicode 的 golden fixtures 与 Vitest / XCTest 双层测试。

## 非范围

- 支持任意传统字符编码；
- 外部文件修改处理（#20）；
- 崩溃恢复（#21）；
- bare CR 只读状态与显式转换 UI（规范 EOL-003，见 `docs/text-format.md` 已知边界）。

## 结果

- 实现：`app/Sources/InkoraDocument.swift`（BOM 剥离/恢复、UTF-16/32 明确错误）、`editor/src/editor-kernel.ts`（EOL-002 插入继承）、`editor/src/editor-runtime.ts`（CR 文档路由源码模式、结构化尾部换行恢复）；
- Fixtures：`tests/fixtures/utf8-bom.md`、`tests/fixtures/mixed-eol.md`、`editor/test/fixtures/markdown/unicode.*.md`、`editor/test/fixtures/markdown/crlf.*.md`，`.gitattributes` 保护字节；
- 测试：InkoraDocumentTests 7 个新用例、EditorWebViewTests 1 个新用例及 fixture 列表扩展、editor-kernel/runtime/markdown-codec 测试扩展；
- 与规范的差异（打开失败 vs 只读状态、bare CR 可编辑、ENC-005 无 API、FID-002 范围映射）记录于 `docs/text-format.md`「已知边界」。
