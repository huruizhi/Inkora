# INK-M1-018：标题 CRLF 范围错误修复与文档约定恢复

- 分支：`task/INK-M1-018-heading-eol-boundaries`；基线 `cf71e3944a837c15b777dab5c6e1db00036bb2a7`。
- 仅修改 4 文件：`editor/src/document-analysis.ts`、`editor/src/document-analysis.test.ts`、`docs/document-analysis.md`、本文件。

## 现象（复现）

管理者冻结用例（`root-m1-checks/html-and-heading-boundary-review.test.ts`，
SHA-256 `829b80b2…46a6a15`）8 项中 2 项红：

- ATX：`\uFEFF# 甲\r\n\r\n## 乙\r\n` 首标题 slice 实为 `# 甲\r\n`，契约 `# 甲`；
- Settext：`甲\r\n===\r\n\r\n# 乙\r\n` 首 slice 实为 `甲\r\n===\r\n`，契约 `甲\r\n===`。

LF 与孤立 CR 同形控制均通过 → 缺陷仅限 CRLF 路径。

## 根因

`buildParseCopy` 归一化 CRLF 时先执行 `i += 1` 跳过 `\n`，再 `toRaw.push(i + bomLength)`，
导致归一化换行映射到原文 `\n` 位置而非起始 `\r` 位置（偏移 +1）。下游
`analyzeDocument` 以 `rawNext = toRawOffset(copy, nextLineStart)` 取次行原文起点后，
用 `slice(-2) === "\r\n"` / 单字符探测剥离尾随 EOL；映射错位使探测落在 `\n\r`
上只剥 1 字符，`end` 多含一个 CRLF。

验证假设的方法：仅交换 push 与跳过顺序（一行级改动），两条红转绿，
token.map / endLine / lineStarts 逻辑不动，LF、孤立 CR、HTML 共 6 项控制不受影响。

## 修复

`editor/src/document-analysis.ts` `buildParseCopy`：先 `toRaw.push(i + bomLength)`
（指向 `\r`）再跳过 `\n`。未改 raw/revision/计数口径与 excludedRanges 校验。

## 回归覆盖（document-analysis.test.ts 新增 5 项）

CRLF 下：标题后空行/连续空行（含 BOM，首标题 end 不含 CRLF）、无空行且 EOF 无尾
EOL（end 到标题末字符）、Settext 下划线行尾 CRLF、嵌套引用/列表原始起止（含容器
标记，契约与既有约定一致）含中文/emoji、excludedRanges 屏蔽后偏移不漂移。边界
expected 由原字符串 `indexOf` 独立定义，不用实现反推。

## 文档恢复

`docs/document-analysis.md` 恢复 cf71e394 误删的契约句：
"尾随 EOL 指 LF、CRLF 或孤立 CR；标题 `end` 均不含尾随 EOL，其余按原文折算。"
保留新增的 HTML tokenization 两条声明，不因 Bug 调整验收口径。
