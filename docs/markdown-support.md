# Markdown 1.0 支持矩阵与数据保真规则

- 状态：已按 ADR-0004 同步
- 版本：1.1
- 生效日期：2026-11-09
- 适用范围：文档读取、结构化编辑、源码编辑、序列化与保存
- 变更方式：任何规则或矩阵变更必须通过独立任务评审，并同步调整受影响的 golden fixtures

本文档是 Inkora 1.0 Markdown 支持级别与 golden fixtures 的 canonical 矩阵；内容权威、投影与保存契约以 ADR-0004 和 V1 生产规格为架构依据。实现与矩阵目标之间的缺口必须单独记录，不能通过降低支持级别掩盖，也不能把未验收目标写成已实现。

## 当前实现状态（生产 V1/V3 非UI候选）

- `SYN-S001` 至 `SYN-S008`、`SYN-S010` 的链接部分、`SYN-S011` 至 `SYN-S013`、`SYN-S015` 已接入原文权威的基本编辑路径；仍以本矩阵 fixtures 为完整验收范围。
- `SYN-S009` 任务列表与 `SYN-S014` 表格已接入生产 schema、原文账本、EditorView/NodeView、main 与 Bridge snapshot 路径；冻结12例及独立非UI接缝已通过。真实 WK/物理输入法、VoiceOver 与正式 NSDocument 文件保存重开仍由管理者验收，当前仅为 V3 非UI完成候选。
- `SYN-S010` 图片保持 S 级首阶段目标；V1 只提供逐字节占位/局部原文路径，完整直接交互由 V4 补齐，当前不得冒称已验收。
- 图片资源 owner 以实际编辑器 accepted 语义投影为唯一权威，并与同一 snapshot 的 document/revision/逐字 raw 绑定。Native 不再独立扫描 Markdown 推断 owner；缺失 proof 与已证明空数组必须区分。
- `D` 级稳定片段可与可视正文混排并逐字节保留；块内编辑使用主动源码草稿。畸形或边界未证明的输入保留完整当前原文、可信投影和诊断，并阻断不安全快照，修复后可恢复。
- bare CR 仍按 `EOL-003` 只读。可视查找替换仍由 V6 完成；源码导航和原子替换继续可用。

## 1. 术语与支持级别

| 级别 | 含义 | 结构化编辑 | 保存策略 |
| --- | --- | --- | --- |
| `S` 支持 | 1.0 理解其结构与语义，并有确定的编辑、序列化行为 | 可编辑 | 通过保真检查后可保存 |
| `D` 延后 | 已识别，但 1.0 不承诺理解或编辑其内部结构 | 以原始片段只读显示；主动源码草稿可精确修复 | 片段逐字节保留时可保存；主动源码提交按 `GATE-004` |
| `U` 不支持 | 1.0 无法可靠识别边界或保证往返安全 | 保留可信投影与完整原文，禁止猜测结构化编辑 | 阻断不安全快照并开放主动源码修复；`ENC-002` 的无效编码保持只读 |

“源码模式”仍须遵守编码与写盘规则。它不是绕过保存闸门的后门，而是让用户显式直接编辑完整原文（包括 `D` / `U` 范围）、避免结构化转换的安全路径；此时保存按 `GATE-004`，不再要求被用户修改的 `D` 片段与输入逐字节一致，但 `ENC-002` 与 `EOL-003` 的只读状态优先。

## 2. 数据保真契约

### 2.1 保真级别

| 规则 ID | 契约 |
| --- | --- |
| `FID-001` | 文档打开后未发生内容修改时，保存结果必须与输入**逐字节一致**，包括 BOM、换行符、尾部换行和所有空白。 |
| `FID-002` | 局部编辑只允许改变用户实际编辑的源范围，以及保持语法有效所必需的最小外层定界符。该最小范围之外的前缀、后缀和不相交原始片段必须逐字节保留。 |
| `FID-003` | 已修改的 `S` 级结构必须准确表达用户明确要求的语义变化；该变化之外的语义必须保持，序列化器不得引入额外语义变化。允许的格式归一化仅限第 5 节明确列出的规则。 |
| `FID-004` | 在可视投影中，`D` 级结构必须作为不透明原始片段保存。实现不得解析后重建、转义、缩进或调整其内部换行。主动源码草稿的用户显式编辑按 `GATE-004`。 |
| `FID-005` | 任何结构无法证明满足 `FID-001` 至 `FID-004` 时，必须保留完整当前原文、可信投影与未解决输入意图并阻止不安全保存；不得因一个片段自动把整篇切为源码，也不得静默丢弃、替换或移动内容。主动源码修复始终可达。 |

### 2.2 编码与 Unicode

| 规则 ID | 契约 |
| --- | --- |
| `ENC-001` | 1.0 可编辑输入编码为 UTF-8；允许无 BOM 或 UTF-8 BOM。BOM 的有无必须保留。 |
| `ENC-002` | 非法 UTF-8 或其他编码不得猜测转换。保留原始字节，文档以只读错误状态打开，并要求用户显式转换后再编辑。 |
| `ENC-003` | 不执行 Unicode NFC、NFD、NFKC 或 NFKD 归一化。组合字符、变体选择符、ZWJ 序列和 emoji 的码点序列保持不变。 |
| `ENC-004` | 中文、其他 Unicode 文本与 ASCII 在语法外均按普通文本等价处理，不得因分词、字体或输入法 composition 改写内容。 |
| `ENC-005` | 内部位置换算必须区分字节偏移、Unicode 标量和 UTF-16 code unit；跨 Swift/JavaScript 边界不得把其中一种偏移冒充另一种。 |

### 2.3 换行、尾部换行与空白

| 规则 ID | 契约 |
| --- | --- |
| `EOL-001` | 必须识别并保留 LF、CRLF 与二者混合边界。每个原始边界分别归属；新换行按 `EOL-002` 继承。不能证明某次编辑的安全往返时按 `FID-005` 保留意图并阻断该次提交，不因 mixed EOL 自动整篇切源码。 |
| `EOL-002` | 新插入的换行优先继承当前行的换行样式；当前行无样式时继承最近的前一行，再退回文档首个换行样式，空文档默认 LF。 |
| `EOL-003` | 文档中出现任一未紧邻 LF 的 bare CR 时，整篇归为 `D`，且是 `GATE-004` 的只读例外；这同时覆盖全 CR 和 CR/LF/CRLF 混合文档。可视投影与主动源码草稿均只允许 byte-identical roundtrip；用户必须先显式将整篇换行转换为 LF 或 CRLF，转换成功后才可编辑。INK-054 选择显式整篇转为 LF（Command-Option-L / 转换按钮），转换不可撤销且立即 dirty、不自动保存；保存前原文件不变。 |
| `EOL-004` | 文件是否以换行结尾是文档状态的一部分。打开或保存不得自动添加或删除尾部换行。 |
| `WSP-001` | 行尾空格、Tab、空行数量和缩进均为源数据；未编辑范围必须原样保留。 |
| `WSP-002` | 两个及以上行尾空格可能表示硬换行，不得由 trim、格式化或 HTML 渲染结果反推原文。 |
| `WSP-003` | 代码块、列表和引用中的缩进具有语义。无法确定归属的空白边界必须扩大为不透明片段或触发保存闸门。 |

## 3. Markdown 1.0 支持矩阵

语义基线采用 [CommonMark 0.31.2](https://spec.commonmark.org/0.31.2/)；标记为 GFM 的扩展采用 [GitHub Flavored Markdown 0.29-gfm](https://github.github.com/gfm/)。两者冲突时以 CommonMark 0.31.2 为准，GFM 仅补充本文明确列出的扩展。这里的版本用于限定语法语义，不要求选择特定解析器。

### 3.1 支持（`S`）

| 规则 ID | 结构 | 1.0 行为与边界 |
| --- | --- | --- |
| `SYN-S001` | 普通段落与纯文本 | 保留源文本；中文、emoji、组合字符与双向文本均适用 `ENC-*`。 |
| `SYN-S002` | ATX / Setext 标题 | 两种写法语义等价，但未编辑时不得互换。支持 1–6 级。 |
| `SYN-S003` | 强调与加粗 | 支持 `*`、`_`、`**`、`__` 的 CommonMark 规则；未编辑定界符不归一化。 |
| `SYN-S004` | 行内代码 | 保留反引号定界符长度和内部空白；编辑后原定界符仍有效时必须保持不变，只有与新内容冲突时才改用不会冲突的最短定界符。 |
| `SYN-S005` | 围栏代码块 | 支持反引号或波浪线围栏、可选 info string，也支持文件末尾前没有 closing fence 的合法块；内容逐字符保留。编辑后现有围栏仍有效时保持标记类型与长度。若内容中出现可被解析为 closing fence 的行（至多 3 个前导空格、同类标记连续 run、其后仅空格或 Tab），新 opening 长度取“原 opening 长度”与“最长候选 run + 1”中的较大值。无 closing fence 时只更新 opening；有 closing fence 且原长度不少于新 opening 时原样保留，否则只增长到新 opening 长度。围栏永不缩短；后接非空白字符的 run 不参与计算。 |
| `SYN-S006` | 缩进代码块 | 按 CommonMark 识别；不得自动转换为围栏代码块。边界不确定时适用 `WSP-003`。 |
| `SYN-S007` | 块引用 | 支持嵌套；未编辑行的 `>` 后空格样式保持不变。 |
| `SYN-S008` | 无序与有序列表 | 支持嵌套、紧凑/宽松列表和起始序号；未编辑的 `-`、`+`、`*` 与编号样式不归一化。 |
| `SYN-S009` | 任务列表（GFM） | 支持 `[ ]`、`[x]`、`[X]`；切换状态只修改括号内字符。 |
| `SYN-S010` | 链接与图片 | 支持行内、引用式和 CommonMark 尖括号自动链接；保留 title、尖括号和引用标签原始写法。 |
| `SYN-S011` | 转义与字符引用 | 支持 CommonMark 反斜杠转义和实体；不得把原始字符与实体表示互相替换。 |
| `SYN-S012` | 主题分隔线 | 支持 CommonMark 写法；不得与列表项静默互换。 |
| `SYN-S013` | 软换行与硬换行 | 支持反斜杠硬换行和空格硬换行；源表示必须保留。 |
| `SYN-S014` | GFM 表格 | 支持表头、分隔行、对齐标记和转义管道；单元格不支持块级结构。 |
| `SYN-S015` | 删除线（GFM） | 支持成对 `~~`；未编辑时保留定界符。 |
| `SYN-S016` | 自动链接扩展（GFM） | 支持裸 URL 与邮箱识别；源文本保持不变。 |

### 3.2 延后（`D`，识别并不透明保留）

| 规则 ID | 结构 | 1.0 行为 |
| --- | --- | --- |
| `SYN-D001` | YAML / TOML front matter | 仅在文件开头（可位于 UTF-8 BOM 后）识别：YAML 以独占一行的 `---` 开始，以后续首个独占一行的 `---` 或 `...` 结束；TOML 以独占一行的 `+++` 开始和结束。围栏与内部内容整体不透明保留。 |
| `SYN-D002` | 脚注 | label 只允许一个或多个 ASCII 字母、数字、`_`、`-`，不支持转义。引用必须完整匹配 `[^label]`。定义首行必须从行首以 `[^label]:` 开始，冒号后允许空格或 Tab；后续非空行只有以至少 4 个空格或 1 个 Tab 开始才属于定义，定义在首个缩进不足的非空行前结束。定义内部的空行仅当其后仍有合法缩进续行时计入定义。定义与引用均不做结构化编辑。 |
| `SYN-D003` | 块级数学公式 | 仅识别以独占一行的 `$$` 开始和结束的块，围栏与内部内容整体不透明保留。行内 `$...$` 因边界歧义归入 `SYN-U005`。 |
| `SYN-D004` | 原始 HTML 块与行内 HTML | 按 CommonMark 0.31.2 的 HTML block 与 raw HTML 边界识别，但排除由 `SYN-D005` 唯一负责的 HTML 注释；源片段只读保留。 |
| `SYN-D005` | HTML 注释 | 按 CommonMark 0.31.2 的注释边界识别并作为独立原始片段保留，不把注释内容解析为 Markdown；同一范围不得再生成 `SYN-D004` 节点。 |
| `SYN-D006` | Wiki 链接与 Obsidian embed | 识别单行内的 `[[target]]` 与 `![[target]]`；target 不得为空、含换行或嵌套 `[[` / `]]`。完整词法范围作为不透明片段。 |
| `SYN-D007` | Obsidian callout | 起始行必须从行首匹配 `>`、可选一个空格、`[!TYPE]`；TYPE 为一个或多个 ASCII 字母、数字、`_`、`-`。`]` 后可紧跟一个 `+` / `-`，标题如存在必须再以至少一个空格或 Tab 分隔。范围只包含起始行及其后连续以 `>` 开始的行（含仅有 `>` 和可选空格的引用空行），首个不以 `>` 开始的行立即结束范围；不接受 lazy continuation。整段不透明保留。 |
| `SYN-D008` | 含 bare CR 的文档 | 按 `EOL-003` 处理。 |

### 3.3 不支持（`U`，保留可信投影、阻止不安全保存并开放源码修复）

| 规则 ID | 结构 | 1.0 行为 |
| --- | --- | --- |
| `SYN-U001` | MDX / JSX / 模板表达式候选 | 在代码、转义、链接目标/title/autolink 与已归属 `D` 的范围之外识别候选并按 `FID-005` 保留原文、可信投影与诊断：行首 `import` / `export` 后跟空白或 `{`；`<` 后可带 `/`、再跟 ASCII 大写字母开头的标签名，且标签名后为 `>`、`/` 或空白；未转义的 `{` 或 `}`。大写 JSX 候选优先于 `SYN-D004` raw HTML；文件开头的 `{` 先按 `SYN-U005` JSON 候选归类。 |
| `SYN-U002` | 未知或畸形的扩展候选 | 以下候选在代码/HTML 字面范围外出现但未完整匹配对应 `D` 规则时，按 `FID-005` 保留原文、可信投影和诊断并阻断快照：文件开头独占一行的 `---` / `+++` 无合法结束围栏；独占一行的 `$$` 无结束围栏；从 `[^` 开始到 `]` 或行尾的脚注候选 label 非法或缺少 `]`；非法 wiki / embed / callout 候选，以及其他无法证明边界的自定义容器、指令或插件语法。 |
| `SYN-U003` | 交叠或解析结果不稳定的扩展语法 | 不选择“最像”的解释；结构化模式禁用。 |
| `SYN-U004` | 非法 UTF-8 或未知编码 | 按 `ENC-002` 只读保留。 |
| `SYN-U005` | 无围栏 JSON front matter、定义列表、上标、下标、mark 与行内数学 | 1.0 不定义这些方言的边界。以下任一候选出现时按 `FID-005` 保留并阻断不安全快照：可选 BOM 后以 `{` 开始的文件；非空行后紧跟以 `: ` 开始的行；成对的 `^...^`、单波浪线 `~...~`、`==...==` 或未转义 `$...$`。 |

## 4. 未知结构与保存闸门

读取与保存必须按以下顺序决策：

1. 保存原始字节，并建立可追踪到原始字节范围的文档表示。
2. 检测编码与换行，并在可选 BOM 后优先识别 `SYN-D001` front matter；合法范围一旦成立，不再执行内部语法检测，只有开始围栏而无合法结束围栏则立即归入 `SYN-U002`。
3. 对其余内容先按 CommonMark 规则锁定围栏/缩进代码块，再依次判定 callout、块级数学和脚注定义的合法或畸形候选，并锁定合法 `D` 外层范围。随后锁定 HTML 注释；仅当尚未占用的块从同一起始位置既可作为 raw HTML 又匹配大写 JSX 时，归入 `SYN-U001`，其他 HTML 块归入 `SYN-D004`。最后识别行首 ESM 候选并完成其余 CommonMark 块级分类。精确匹配 `SYN-D002` 的脚注定义优先于同形的 link reference definition。
4. 对仍未占用的行内内容先按 CommonMark 边界锁定行内代码和反斜杠转义的标点字符，再同时发现精确合法的脚注引用与完整 CommonMark 链接、图片、link destination、title、autolink 范围。候选交叠时，更早起点的完整外层范围优先；只有同一起点竞争时，合法脚注才优先于 shortcut/collapsed/full reference link。锁定胜出范围后，再处理 HTML 注释；仅当尚未占用的行内范围从同一起始位置既可作为 raw HTML 又匹配大写 JSX 时，归入 `SYN-U001`，其他 raw HTML 归入 `SYN-D004`。最后在未占用范围判定畸形脚注与 wiki link / embed 候选，畸形候选归入 `SYN-U002`。
5. 最后只在尚未占用的普通文本范围检测模板花括号及其他 `U` 候选；检测失败不得假定为普通段落。代码、链接目标/title/autolink、raw HTML 与其他已锁定范围内的候选永不触发更低优先级 `D` / `U` 检测。
6. `S` 结构可进入结构化编辑；`D` 结构必须以不可编辑原始片段参与范围映射。
7. 发现 `U` 结构、边界重叠或偏移映射失效时，保留唯一当前原文、最后可信投影和完整未解决意图，阻断不安全快照并开放主动源码修复；不得仅因局部候选自动切换完整文档源码。
8. 保存前按当前编辑路径选择且只选择一条校验：可视投影验证所有原始范围恰好属于“未触及”“已修改的 `S` 结构”或“完整 `D` 片段”之一，不得存在缺口、重复或重排；主动源码提交验证完整草稿可无损编码为 UTF-8，且输出只来自该草稿、不经过结构化格式化。
9. 验证失败时阻止保存，保留内存中的用户编辑，并明确指出失败范围与恢复选项。

| 规则 ID | 保存闸门 |
| --- | --- |
| `GATE-001` | 未修改文档只有在输出字节与输入字节一致时才可完成保存。 |
| `GATE-002` | 结构化模式中，任一 `D` 片段发生改写、范围破损或隐式归一化时阻止保存。 |
| `GATE-003` | 结构化模式中，任一原始字节未被范围映射覆盖，或被多个节点重复覆盖时阻止保存。 |
| `GATE-004` | 用户主动进入源码并显式提交完整原文后，可按新 UTF-8 字节保存；保存前仍须验证文本可无损编码，且不得自动格式化。 |
| `GATE-005` | 保存失败不得写入部分输出或丢弃内存中的用户内容；取消后仍保留失败前的编辑缓冲区。 |

## 5. 允许的格式归一化

默认不做文档级格式化。只有用户实际修改的最小 `S` 结构可以使用下列确定性规则：

- 新建无序列表默认使用 `- `，新建有序列表默认从 `1. ` 开始；已有相邻列表延续其标记风格。
- 新建 ATX 标题使用 `#` 后一个空格，不自动添加尾部 `#`。
- 编辑行内代码时保留现有反引号长度；仅当新内容与现有定界符冲突时，改用不会冲突的最短长度。
- 新建围栏代码块默认使用三个反引号；已有围栏按 `SYN-S005` 的公式只做必要增长。原块无 closing fence 时不得凭空添加；已有 closing fence 足够长时不得缩短或改写。
- 新建表格使用一个空格包围单元格内容；已有未编辑表格的列宽和空格不对齐。
- 新插入换行按 `EOL-002`；是否保留尾部换行按 `EOL-004`。

除此之外，定界符替换、引用标签重命名、列表重新编号、HTML 实体转换、空白清理、Unicode 归一化和整篇重排均不允许隐式发生。

## 6. Golden fixture 清单

每个 fixture 由原始输入文件、操作描述和期望输出组成，并在元数据中引用下表规则 ID。`roundtrip` 表示“打开后不修改并保存”；`edit` 表示执行最小编辑后保存。二进制异常样本不得以文本工具重写。

## 7. 后续实现的最低验证要求

后续 schema、解析器或编辑内核任务在声称支持本规范前，至少必须：

1. 为其涉及的每个规则 ID 建立自动化测试映射；
2. 实体化第 6 节相关 fixtures，并保留输入文件的原始字节；
3. 对所有 roundtrip fixture 使用字节比较，而不是字符串或渲染结果比较；
4. 对局部编辑比较未触及范围的字节切片；
5. 对失败场景验证“未写盘”和“用户缓冲区未丢失”两项结果；
6. 报告尚未覆盖的规则 ID，不得把未测行为视为已支持。
