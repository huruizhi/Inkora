## 红绿反馈环

### 旧 runtime 结果越过新 load

新增 production runtime 回归后执行：

```text
vitest run editor/src/visual-search-runtime.test.ts -t "previous runtime load"
```

RED 为 `1 failed / 35 skipped`：新 runtime 对旧结果导航实际返回 `ok: true`，而不是
“查找结果已过期”。根因是 runtime 只用 `sameSearchResult` 比较可视文本、revision、query
和 matches；`loadEpoch` 仅在 main/SearchPanel 外壳，runtime 公共能力没有结果来源。

补正后限定控制为 `3 passed / 40 skipped`：相同文档不同 epoch、相同 epoch 不同文档均拒绝
导航与替换；当前 runtime 的稳定重复查询与 JSON 值拷贝仍通过。拒绝操作保持 raw、dirty、
history 与 savepoint 不变。

### CommonMark 嵌套 marks

新增真实 runtime 回归后执行：

```text
vitest run editor/src/visual-search-runtime.test.ts -t "CommonMark nested emphasis"
```

RED 为 `1 failed / 37 skipped`：PM DOM 已有 strong/em，查询 `alpha omega` 得 1 处，但初始
`saveEligible` 为 `false`。根因是 ledger 的首次字符串匹配把结尾 `***` 的前两个字符误作
外层 strong close，内层 em 无法获得自己的 close，最终词法 atom 与 PM 叶不一致。

补正后的限定命令：

```text
vitest run editor/src/visual-search-runtime.test.ts -t "nested same-marker runs|nested-mark bytes"
```

结果为 `5 passed / 37 skipped`。覆盖 `**alpha *omega***`、`__alpha _omega___`、
`*alpha **omega***`、`_alpha __omega___`，核对 replacement 继承起点 marks、原始星号/下划线
风格、反向选区、源码 caret、Undo/Redo、saveEligible 和 no-op future。定界符来源取自
markdown-it 已完成的 CommonMark 配对；未放宽候选 PM 等价或建立字符串特例表。
